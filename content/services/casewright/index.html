Casewright

요구사항 정의서·기획서·화면설계서를 올리면 근거를 붙인 테스트 케이스(TC)를 만들고, 추천 양식이나 직접 올린 양식의 엑셀로 내보내는 웹 서비스. 판정은 코드의 게이트가 하고 AI는 제안만 합니다.A web service that turns requirement, planning and screen-design documents into evidence-backed test cases and exports them to Excel, in a recommended form or one you upload. Code-based gates make the judgments, and the AI only proposes.

서비스 열기Open the service

주요 기능Main features

  • 일곱 단계, 단계마다 게이트Seven stages, a gate at each 설정 → 자료 → 요구사항·조건 → 설계 → 테스트 케이스 → 게이트·추적표 → 내보내기. 27개 게이트가 PASS / FAIL / UNKNOWN으로 판정하고 빈 입력은 "판정 불가"입니다.Setup, documents, requirements and conditions, design, cases, gates and traceability, export. 27 gates return PASS / FAIL / UNKNOWN; empty input is "cannot judge".
  • 근거 없는 TC를 걸러냅니다Filters out unsupported cases 모든 조건 · 예상 결과에 원문 인용을 요구하고 코드가 원문과 대조합니다. 문서에 없는 결과는 지어내지 않고 "근거 없음"으로 남깁니다.Every condition and expected result needs a source quote that code verifies. Results missing from documents are left as "no evidence" instead of invented.
  • 기법의 산술은 코드가Technique math done by code 동등분할 · 경계값 · 결정 테이블 · 상태 전이 · 페어와이즈 조합은 AI가 아니라 코드가 계산합니다. AI는 문서에서 범위 · 규칙 · 상태를 "찾기"만 합니다.Equivalence classes, boundaries, decision tables, state transitions and pairwise combinations are computed by code; AI only finds ranges, rules and states in the documents.
  • 양방향 추적표(RTM)Two-way traceability (RTM) 요구사항마다 TC가, TC마다 요구사항이 있는지 보여 주고 빈 곳을 짚습니다.Shows whether each requirement has cases and each case has a requirement, and points out the gaps.
  • 내 양식 그대로 내보내기Export in your own template 추천 양식 4종 또는 내 엑셀 양식에 맞춰 서식 · 병합 · 열 너비를 보존해 채우고, 만든 파일을 다시 읽어 검증합니다.Fill one of four recommended templates or your own Excel while preserving formatting, merges and widths, then re-read the file to verify.
  • 사람이 고친 TC는 보존Human edits are kept 사람이 고치거나 승인한 TC는 재생성해도 보존됩니다. 모호한 곳은 질문으로 돌려줍니다.Cases you edit or approve survive regeneration, and ambiguous points come back as questions.

이런 분께 맞습니다Who it is for

  • 요구사항 정의서 · 기획서 · 화면설계서를 바탕으로 테스트 케이스를 써야 하는 QA · 테스터QA engineers and testers writing test cases from requirement, planning and screen documents
  • 경계값 · 조합 · 결정 테이블 계산을 손으로 하다 빠뜨림이 걱정되는 개발자Developers worried about missing boundary, combination and decision-table cases when computing by hand
  • 요구사항 ↔ TC 추적표를 제출해야 하는 SI · 납품 프로젝트 PMPMs on SI or delivery projects who must submit a requirement-to-test traceability matrix
  • 회사나 발주처가 정한 엑셀 TC 양식에 그대로 채워야 하는 팀Teams that must fill a company- or client-defined Excel TC template

사용 방법How to use

  1. 테스트 레벨(단위 · 통합 · 시스템 · 인수)과 제품 유형, 사용 환경, 출력 양식을 정합니다.Set the test level, product type, environments and output template.
  2. 요구사항 정의서 · 기획서 · 화면설계서를 올립니다(XLSX · DOCX · PPTX · PDF · CSV · TXT).Upload requirement, planning and screen documents (XLSX, DOCX, PPTX, PDF, CSV, TXT).
  3. 조건 추출과 설계 기법 선택을 확인하고 테스트 케이스를 검수합니다.Review extracted conditions and technique choices, then inspect the generated cases.
  4. 게이트와 추적표를 통과시킨 뒤 엑셀(.xlsx)로 내보냅니다.Pass the gates and traceability check, then export to .xlsx.

알아둘 점Good to know

  • AI 판단은 서버가 아니라 내 PC의 Claude Code · Codex(내 구독)가 합니다. 서비스 서버에는 모델이 없습니다.The AI work runs on your own PC through Claude Code or Codex (your subscription). The service server has no model.
  • 필수(E) 게이트가 하나라도 실패하면 제출용 내보내기는 막히고, 경고(W)는 남겨 두고 내보낼 수 있습니다.If any mandatory (E) gate fails, submission export is blocked; warnings (W) can remain.
  • 결과 기록 · 회귀 선별 기능은 준비 중입니다.Result logging and regression selection are still in preparation.
