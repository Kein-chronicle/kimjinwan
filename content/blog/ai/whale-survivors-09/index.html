게임 이미지 검수와 용량 감사: 카드·액션·파일·프레임을 나누는 법

기록일 2026. 8. 21.수정 2026. 10. 13.

표시 날짜는 모바일 자산 감사 기록의 대표일입니다. 2026년 10월 14일 원격 원본을 다시 읽고 5월 이미지 규격 글과 통합했습니다.

이 글의 목적

AI 게임 이미지를 생성·교체하고 모바일 자산을 줄일 때 수령 규격과 감사 단위를 혼동하지 않도록 돕는다.

핵심 내용

7개 수령 파일 중 동작 프레임은6개일 수 있고,207MB와207프레임은 다른 범위다. 실행 자산 원장을 기준으로 교체와 용량 측정을 나눈다.

읽고 나서

한 줄 요약: 게임 이미지는 사용 위치·표시 규격·프레임 수로 검수하고, 제작 폴더 용량·실행 자산 용량·최종 설치 용량을 따로 기록한다.

카드에서 멋있던 그림을 작은 전투 효과로 쓰면 무엇을 쏘는지 알아보기 어려울 수 있다. 파일을 줄였는데 필요한 프레임까지 빠지는 경우도 따로 확인해야 한다. 이 글은 카드·액션 이미지의 수령 기준과 모바일 자산 감사표를 한 흐름으로 정리한다.

웨일서바이버의 5월 이미지 생성 계약과 재생성 수령함 규칙, 8월 모바일 분석·프레임 감사 문서를 2026년 10월 14일 원격 저장소에서 다시 읽었다. 아래 수치는 해당 문서가 기록한 당시 범위다. 현재 게임을 빌드하거나 실기기 용량·성능을 새로 측정한 결과는 아니다.

카드 그림과 액션 프레임은 받는 기준부터 다르다

5월 20일 기준 공통 계약은 자산 정보·사용 위치·출력 형식·프레임 구성·스타일·금지 사항·검수 기준 순서로 요청을 정리한다. 특히 카드 이미지와 전투 동작 이미지를 한 파일에 섞지 않도록 한다. “예쁜 그림”만으로는 어디에 넣을 수 있는지 결정할 수 없기 때문이다.

항목 카드 중앙 이미지 전투 액션·투사체
독자가 봐야 할 것 어떤 카드인지 구별되는 대상과 실루엣 공격 방향·범위·동작 단계
배경 문서상 중앙 이미지는 투명 PNG 대상 문서상 효과·투사체도 투명 PNG 대상
여백 카드 이미지 영역 안 사방 12% 일반 오브젝트 사방 18%, 긴 창·레이저 등 24%
비교 크기 실제 카드 화면의 축소 크기 실제 전투 화면의 표시 크기
연속 프레임 정지 그림이면 해당 없음 중심축·크기·잘림을 프레임끼리 비교
연결 정보 카드 ID와 그림 경로 자산 ID·프레임 순서·시트 규격·코드 경로

여백 비율은 이 프로젝트 계약의 수치다. 다른 게임에 그대로 적용하는 표준값은 아니다. 카드가 작거나 UI가 다르면 실제 표시 크기에서 다시 정한다. 출력 해상도와 화면에서 보이는 크기를 구분하고, 검수 요청에 둘을 함께 적는다.

투명 PNG라는 확장자만으로 배경 처리가 올바른지 알 수는 없다. 밝은 배경과 어두운 배경 위에 각각 올려 불투명 테두리나 색 번짐을 살핀다. 액션은 프레임을 순서대로 재생해 중심이 흔들리지 않는지, 끝부분이 잘리지 않는지 본다. 이 시각 검사는 아래 파일 개수 검사로 대체되지 않는다.

보존된 5월 검수용 모음. 실제 전투 성능이나 개별 이미지의 최초 생성일을 증명하는 자료는 아니다.

재생성 결과를 바로 덮어쓰지 않는다

재생성 수령함 README는 리소스마다 별도 폴더를 만들고, sample.png와 frame01.png부터 frame06.png까지 받도록 정한다. 수령 파일은 7개지만 그중 동작 프레임은 6개다. 이 차이를 놓치면 샘플 그림까지 동작 프레임으로 셀 수 있다. 당시 수령함의 169개 리소스라는 수치도 파일 169개나 최종 게임 프레임 169개와는 다르다.

문서는 최종 반영 전 실행 자산 폴더에 직접 덮어쓰지 못하게 한다. 아래 순서는 그 규칙을 실제 작업에 적용하기 위한 제안이다.

  1. 기존 파일과 새 후보를 서로 다른 위치에 둔다. 후보 ID·생성 조건·요청한 규격을 함께 기록한다.
  2. 필수 파일 누락과 이름을 검사한다. 샘플·프레임·검수판의 역할을 구분한다.
  3. 같은 배경과 같은 표시 크기에서 기존·신규를 비교한다. 큰 원본만 보고 고르지 않는다.
  4. 액션 재생과 게임 화면 연결을 확인하고 채택 여부를 기록한다. 보류 후보는 실행 목록에 넣지 않는다.
  5. 채택한 파일만 교체하고 이전 버전으로 복구할 경로와 승인 근거를 남긴다.

수령 완료, 시각 검토 통과, 코드 연결 완료, 실제 플레이 확인은 서로 다른 상태다. “이미지 완성” 하나로 묶으면 어느 단계에서 문제가 생겼는지 알기 어렵다.

같은 207이라도 MB와 프레임은 다른 숫자다

8월 모바일 분석 문서는 약 2.1GB의 원본에서 런타임 참조 자산 1,485개를 선별하고 WebP·AAC로 최적화해 약 207MB로 줄였다고 기록한다. 이는 당시 선별·최적화 작업에 대한 문서 기재값이다. 207MB를 최종 IPA 크기나 앱 설치 크기로 쓰면 측정 대상이 바뀐다. 선별과 형식 전환이 함께 기록돼 있으므로 감소량 전체를 특정 압축 방식의 효과로 돌릴 수도 없다. 같은 문서의 미완료 목록에는 실제 자산 이관이 남아 있어, 적용 기록과 미완료 항목도 혼재한다. 이 문서만으로 최종 이관 완료 여부까지 판단하지 않는다.

별도의 프레임 감사 문서에는 적 캐릭터·적 효과·무기 동작·기믹의 감사 소계가 207프레임 단위라고 적혀 있다. 같은 문서는 전체 공개 이미지 라이브러리를 245개 물리 이미지 파일, 318프레임 단위로 구분한다. 앞의 207MB와 이 207프레임은 우연히 숫자만 같고 단위와 범위가 다르다.

기록할 숫자 범위와 단위 말할 수 있는 것 이것만으로 알 수 없는 것
제작 폴더 용량 원본·후보·검수판 포함 바이트 작업 자료의 저장량 최종 앱의 다운로드 크기
실행 자산 용량 실제 참조해 빌드에 넣은 파일 바이트 실행 자료 선택 결과 설치 후 크기·실행 메모리
물리 파일 수 파일 경로 중복을 제거한 개수 배포해야 할 파일 수 시트 안의 동작 수
프레임 단위 수 각 시트·단일 이미지의 표시 단위 감사 대상으로 센 표현 수 화면 재생 속도·게임 성능
빌드·설치 크기 산출물과 실제 설치 환경별 바이트 해당 버전·기기의 측정치 다른 OS·기기의 동일 결과

예를 들어 여섯 프레임을 한 시트에 담으면 파일은 하나, 프레임은 여섯이다. 여섯 개 파일로 나눠도 프레임 수는 여섯일 수 있다. 파일 수 감소를 애니메이션 삭제나 성능 개선과 바로 같은 뜻으로 해석하지 않는다.

삭제 전에 실행 자산 원장을 만든다

다음 양식은 새 프로젝트에도 사용할 수 있는 제안이다. 문서의 과거 숫자를 현재 예산으로 복사하는 대신 실제 빌드에서 참조되는 목록부터 만든다.

자산 ID 용도 파일·프레임 구성 참조 위치 채택 상태 검수·복구 근거
예시: card-A 카드 중앙 단일 파일 1, 프레임 1 카드 데이터 ID 채택/보류 축소 비교판·이전 지문
예시: action-A 공격 동작 시트 1, 프레임 6 렌더러 애니메이션 ID 채택/보류 재생 영상·시트 규격
예시: sample-A 후보 검수 단일 파일 1, 실행 프레임 0 검수 문서만 제작용 수령함 경로

동적 경로로 읽는 자산은 단순 문자열 검색에서 빠질 수 있다. 목록을 줄이기 전 로더·데이터 테이블·이름 조합 규칙을 확인한다. “코드에서 파일명 검색 결과가 없다”만으로 삭제하지 않는다. 공용 프레임을 여러 적이 재사용한다면 파일 수는 중복 제거하고, 프레임 단위를 어떤 기준으로 셌는지 원장에 적는다.

교체 뒤에는 시작 화면만 보는 것으로 끝내지 않는다. 해당 무기를 실제로 얻는 경로, 발사·명중·소멸 단계, 다른 해역의 적, 결산 화면까지 변경 자산이 쓰이는 위치를 확인한다. 프레임 감사 문서가 누락된 해역 2·3 적 그림을 복원한 뒤 다시 측정했다고 적은 이유도 파일 목록과 플레이 범위를 함께 봐야 함을 보여준다. 그 기록만으로 현재 모든 화면의 검증이 끝났다는 뜻은 아니다.

현재 빌드의 용량과 성능은 별도 측정표에 버전·기기·화면·측정 방법을 붙인다. 자산을 덜 넣었다는 사실과 게임이 더 잘 돌아간다는 결과를 같은 항목에 적지 않는다. 복구 가능한 교체 단위로 반영하면 문제가 생겼을 때 전체 제작 폴더를 되돌릴 필요도 줄어든다.

세 줄 요약

  • 카드와 액션 이미지는 표시 크기·투명도·여백·프레임 중심을 서로 다른 기준으로 검수한다.
  • 샘플·동작 프레임·물리 파일·용량의 단위를 분리하고, 제작 자료를 실행 자산에 바로 덮어쓰지 않는다.
  • 과거 207MB 기록을 설치 용량으로 바꾸지 말고, 실행 원장과 실제 빌드·기기 측정을 따로 남긴다.
