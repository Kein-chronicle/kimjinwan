작업은 끝났는데 계속 실행 중일 때: 네 시각으로 지연 나누기

기록일 2026. 10. 3.수정 2026. 10. 13.

2026년 10월 14일 관련 시험 26개를 임시 상태로 재실행했습니다. 이전 글의 세 시각 설명을 시작 포함 네 시각으로 정정했습니다.

이 글의 목적

여러 자동 작업을 운영하는 사람이 실행 시간과 완료 인지·다음 배정 지연을 분리해 원인을 찾는다.

핵심 내용

작업 시간을 계산하려면 시작 시각까지 네 시각이 필요하다. 감시 알림은 종료 판정이나 다음 작업 배정과 별개다.

읽고 나서

작업 ID에 시작·결과 확정·종료 확인·다음 배정 시각과 로그 출처를 연결한다.

목차
  • 네 시각으로 세 구간을 계산한다
  • 가상 기록으로 원인 위치를 좁혀 본다
  • 실제 기록에는 완료 감지와 우선순위 두 문제가 있었다
  • 감시는 알리고, 종료 판정은 운영자가 한다
  • 재실행한 시험이 확인한 것
  • 다음 지연 조사에 남길 최소 기록
  • 세 줄 요약

한 줄 요약: 작업 시작·최종 결과 기록·운영자의 종료 확인·다음 배정 네 시각을 남기면 실행 시간, 완료 인지 지연, 다음 배정 지연을 나눠 조사할 수 있다.

작업자가 결과를 냈는데 화면은 계속 실행 중이다. 다음 예약도 밀린다. 이때 상태 화면의 경과 시간을 모델의 실제 작업 시간으로 읽으면 실행 속도를 고치면서 완료 알림 문제를 놓칠 수 있다.

개인 제작 공장의 2026년 10월 3일 인계 기록과 완료 감시·선택 코드를 대조했다. 10월 14일에는 관련 두 시험 모듈의 26개 시험을 임시 상태와 가짜 알림 전송으로 실행해 통과했다. 운영 중인 작업을 시작하거나 실제 운영자에게 알림을 보낸 검사는 아니다.

네 시각으로 세 구간을 계산한다

이전 글은 결과 작성·종료 기록·다음 배정의 세 시각만으로 작업 시간까지 나누려 했다. 작업 시작이 없으면 첫 구간의 실행 시간을 계산할 수 없다. 다음 네 시각이 필요하다.

시각 의미 기록할 때의 조건
t0 작업이 실제로 시작됨 예약 시각·배정 시각과 구분
t1 최종 결과가 읽을 수 있는 상태로 기록됨 부분 파일이나 중간 보고 제외
t2 운영자가 결과·종료 조건을 확인하고 상태를 닫음 단순 알림 전송 시각과 구분
t3 다음 작업을 배정함 실제 다음 작업 시작과 구분 
결과가 나오기까지 = t1 - t0
결과 기록 후 종료 확인까지 = t2 - t1
종료 확인 후 다음 배정까지 = t3 - t2

첫 구간도 CPU가 실제로 계산한 시간만 뜻하지 않는다. 작업 내부의 API 대기와 검토 대기가 들어갈 수 있다. 더 나누려면 작업 내부 사건을 추가로 기록한다. 다음 작업의 실행 지연을 보려면 다음 시작 시각도 별도 남긴다.

가상 기록으로 원인 위치를 좁혀 본다

다음 시각은 계산을 설명하기 위한 가상 예시다.

사건 시각
실제 시작 t0 16:00
최종 결과 기록 t1 16:18
종료 확인 t2 16:31
다음 배정 t3 16:34

결과까지 18분, 종료 확인 대기 13분, 다음 배정 대기 3분이다. 34분 전체를 “제작 시간”으로 보고하면 13분의 완료 인지 지연을 숨기게 된다.

t1은 파일의 수정 시각을 무조건 가져오면 안 된다. 결과 파일을 수정하거나 복사했을 수 있다. 작업 ID, 결과 확정 사건, 로그 출처를 함께 남긴다. 서로 다른 기기의 시계를 쓴다면 시간대와 시계 차이도 확인한다. 순서가 뒤집힌 기록은 음수 지연으로 평균 내기 전에 자료 오류부터 조사한다.

실제 기록에는 완료 감지와 우선순위 두 문제가 있었다

10월 3일 인계 문서는 전날 오후 생산의 실제 배정이 17:03:16이었다고 기록한다. 밀린 점검이 먼저 선택됐고, 작업자 결과만으로 운영자의 새 처리가 시작되지 않아 완료된 작업이 실행 중 상태에 남는 문제도 있었다.

이 두 문제는 다른 수정이 필요하다. 완료 알림을 빨리 보내도 다음 선택이 밀린 점검부터라면 생산은 계속 기다린다. 반대로 생산을 먼저 고르게 해도 이전 실행 중 상태가 닫히지 않으면 선택 단계까지 가지 못한다.

관측 먼저 확인할 곳 곧바로 하면 안 되는 판단
결과가 아직 없음 작업 진행·외부 대기·제한 시간 모델이 멈췄다고 즉시 재실행
최종 결과는 있으나 상태가 실행 중 완료 감시·알림 전송·운영자 수신 같은 작업을 다시 배정
상태는 닫혔으나 다음 배정이 없음 예약 도래·일시정지·의존 조건 완료 감시만 더 자주 돌리기
배정되지만 밀린 점검부터 시작 선택 정책·동일 우선순위 순서 실행 중 작업을 무조건 중단

감시는 알리고, 종료 판정은 운영자가 한다

읽은 감시 코드는 현재 작업의 예상 결과 경로를 확인하고 결과에 outcome과 summary가 있거나 시작 기준 제한 시간이 지나면 알림을 큐에 넣는다. 일시정지, 등록 운영자, 현재 작업 ID도 확인한다. 감시 자체가 작업을 종료하거나 다음 작업을 배정하지는 않는다.

이 결과 필드 확인은 알릴 조건이다. 모든 결과 내용과 실제 프로세스 종료를 검증하는 최종 판정은 아니다. 운영자는 작업자 보고·결과 계약·실제 상태를 대조해야 한다. 시간 상한 알림 역시 실패 확정이나 강제 종료와 같지 않다.

당시 1분 감시는 다음 폴링 기회를 제공한다. 기기 절전, 큐 전송, 운영자 처리 지연까지 포함해 1분 안에 다음 작업이 시작된다는 보장은 아니다.

재실행한 시험이 확인한 것

10월 14일 test_operator_wakeup과 test_scheduler를 실행해 26개 통과를 확인했다. 감시 시험은 임시 폴더와 가짜 전송 함수를 사용한다.

시험 범위 확인하는 계약
같은 완료 사건 반복 감지 같은 실행·운영자의 중복 알림 억제
전송 함수 실패 실패 사건을 완료 전송으로 기록하지 않고 재시도
부분 JSON 뒤 완성 결과 부분 자료로 알리지 않고 이후 재확인
다른 운영자·일시정지 조건이 맞지 않으면 알림을 보내지 않음
예상 밖 결과 파일 경로 다른 파일을 현재 작업 완료로 쓰지 않음
시간이 된 작업 슬롯 슬롯·등록 순서와 지연 판정

별도로 코드를 읽어 확인한 현재 선택 함수의 생산 우선 옵션은 실행할 시간이 된 생산을 먼저 두고, 그 안에서는 슬롯 순서를 사용한다. 이번 26개 시험에는 생산 우선 옵션을 켠 분기의 검사가 포함되지 않았다. 미래 작업을 앞당기거나 이미 실행 중인 작업을 끊는 기능은 이 정렬 함수의 역할이 아니다. 실제 운영에서도 그 정책이 유지되는지는 배정 기록과 실행 제어를 함께 확인해야 한다.

다음 지연 조사에 남길 최소 기록

작업 ID 하나에 네 시각과 사건 출처를 연결한다. 알림은 시도 시각·성공 여부·재시도 여부를 붙이고, 다음 배정에는 선택 후보와 보류 이유를 남긴다. 그래야 “알림을 놓침”과 “의도적으로 대기함”을 구분할 수 있다.

같은 작업을 다시 실행하기 전에는 최종 결과가 이미 있는지부터 본다. 중복 실행은 비용뿐 아니라 같은 외부 변경을 두 번 적용할 수도 있다. 상태를 먼저 읽고 재개 지점을 정하는 편이 안전하다. 예약 정의 자체가 밀리는 문제는 예약 시각이 늦어지는 사례와 구분해서 조사한다.

세 줄 요약

  • 시작·결과 확정·종료 확인·다음 배정 네 시각으로 세 대기 구간을 계산한다.
  • 완료 감시의 알림 조건과 운영자의 종료 판정, 다음 작업의 선택 정책은 별개다.
  • 같은 작업을 재실행하기 전에 기존 결과와 상태를 읽고 알림·배정의 누락 지점을 찾는다.

같이 읽을 글

  • set -e 스크립트가 에러 없이 중간에 끝날 때: 변수에 담은 grep 한 줄 찾기

    set -e를 켠 bash 검사 스크립트가 통과해야 할 때만 아무 메시지 없이 멈췄다. macOS bash 3.2·zsh·sh로 원인(grep의 매치 없음 종료 코드 1)과 세 가지 수정, 수정이 삼키는 오류를 재현했다.

  • macOS에서 grep -P가 안 될 때: 오류가 나는 경우와 조용히 비거나 엉뚱한 결과가 나오는 경우

    macOS 기본 grep에서 grep: invalid option -- P 가 나올 때 대체 방법과, 오류 없이 비거나 엉뚱한 결과가 나오는 \d+·\K 같은 정규식을 이 맥에서 직접 실행해 가려냈다.

  • SwiftUI 공유 시트가 비어 있을 때: item으로 공유 데이터 함께 넘기기

    첫 공유가 빈 시트인 경우를 자체 예제로 대조하고, 선택한 문자열과 Copy 출력까지 확인하는 item 기반 구현을 제공한다.
