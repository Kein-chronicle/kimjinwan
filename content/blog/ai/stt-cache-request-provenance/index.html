STT 캐시 검증: 파일·모델·언어가 바뀌면 재검사됐는가

기록일 2026. 10. 2.수정 2026. 10. 13.

2026년 10월 14일 원본 코드와 기록을 다시 확인해 보강했습니다. 당시 실행과 이번 검사·제안은 본문에서 구분합니다.

이 글의 목적

STT 검수 결과가 현재파일과요청설정을가리키는지확인하고품질검사와분리한다.

핵심 내용

파일·모델·요청언어가일치해도품질통과는아니다. 추가옵션과응답기록및음성수선을분리한다.

읽고 나서

캐시기록옆에현재파일지문·모델·요청언어를놓고설정변경시재사용거부를검사한다.

목차
  • 어떤 입력의 결과인지 먼저 고정한다
  • 보관 함수에 넣은 일곱 가지 입력
  • 요청 조건과 응답 내용을 다른 필드로 남긴다
  • 재전사와 음성 수선을 한 결과로 합치지 않는다
  • 다음 재검사에서 확인할 순서
  • 세 줄 요약

한 줄 요약: STT 캐시는 음성 파일뿐 아니라 모델·요청 언어를 비교해야 하며, 캐시 재사용 가능 판정과 받아쓰기 품질 판정은 별도로 남겨야 한다.

받아쓰기 검사의 언어 설정을 바꿨는데 결과가 그대로다. 모델이 같은 실수를 반복한 것일 수도 있고, 새 요청을 보내지 않고 옛 결과를 읽었을 수도 있다. 캐시가 파일만 비교한다면 설정 변경은 재검사의 증거가 되지 않는다.

개인 영상 제작 저장소의 2026년 10월 2일 커밋 05d594c는 이 재사용 조건에 모델과 요청 언어를 추가했다. 10월 14일에는 보관된 두 함수를 추출해 합성 입력으로 재사용 행렬을 실행했다. 외부 전사 API를 다시 호출하거나 실제 음성을 재생성한 검사는 아니다.

어떤 입력의 결과인지 먼저 고정한다

수정된 코드의 stt_request_inputs()는 음성 지문, 모델 ID, 요청 언어를 묶는다. current_stt_record()는 저장 기록의 같은 세 값과 비어 있지 않은 텍스트를 확인한다.

return (record.get('sig') == audio_sig
        and record.get('model_id') == model_id
        and record.get('language_code') == language_code
        and isinstance(record.get('text'), str)
        and bool(record['text'].strip()))

이것은 해당 프로젝트가 당시 사용하던 요청 조건을 검사하는 코드다. 모든 전사 요청의 완전한 캐시 키라는 뜻은 아니다. 화자 구분, 타임스탬프 단위처럼 결과에 영향을 주는 옵션을 더 쓰기 시작하면 그 옵션도 입력 기록과 재사용 정책에 포함해야 한다.

ElevenLabs 전사 API 문서는 모델 지정과 선택적 언어 힌트, 화자 구분·타임스탬프 등의 요청 항목을 설명한다. 언어를 생략하면 자동 예측하며 힌트는 성능을 도울 수 있지만 성공을 보장하지 않는다. 문서의 옵션이 늘어날 때도 저장 키가 실제 요청을 빠뜨리지 않는지 점검할 필요가 있다.

보관 함수에 넣은 일곱 가지 입력

다음 표는 2026년 10월 14일 실제 보관 함수의 조건식을 실행한 결과다. 음성 지문 a, 모델 m1, 언어 ko, 비어 있지 않은 텍스트를 기준 기록으로 두었다. a와 m1은 시험용 문자열이다.

바꾼 것 함수의 재사용 판정 해석
아무것도 바꾸지 않음 허용 현재 요청의 세 입력과 텍스트 조건 일치
음성 지문 a→b 거부 다른 음성의 결과
모델 m1→m2 거부 다른 모델 요청
요청 언어 ko→kor 거부 문자열이 다른 요청 조건
모델·요청 언어 없는 옛 기록 거부 현재 요청을 증명할 입력 기록 부족
텍스트를 공백만 남김 거부 결과 텍스트 조건 미충족
응답 언어만 en으로 추가 허용 이 함수는 응답 언어의 적합성을 검사하지 않음

일곱 판정과 요청 입력 묶음의 언어 변경 검사 한 건, 총 여덟 검사가 기대 결과와 일치했다. 전사 정확도나 전체 파이프라인의 캐시 저장·복구까지 확인한 것은 아니다.

특히 마지막 행이 중요하다. 현재 입력과 맞는 기록이라고 해서 원하는 언어를 정확히 받아쓴 결과라는 뜻은 아니다. 캐시 재사용을 통과한 뒤에도 대본 대조, 고유명사, 실제 음성 청취 같은 품질 검사가 필요하다.

ko와 kor의 차이도 과장하면 안 된다. 공식 문서는 두 글자·세 글자 언어 코드를 허용하고, 당시 인계 기록은 두 한국어 표기를 유효한 요청으로 다룬다. 위 함수는 언어의 의미를 정규화하지 않고 문자열을 비교하므로 값이 바뀌면 재사용을 거부한다. 이 결과로 어느 표기가 음질 문제의 원인이었다고 판정할 수는 없다.

요청 조건과 응답 내용을 다른 필드로 남긴다

당시 수정은 텍스트 외에 요청 모델·언어, 응답 언어, 언어 확률, 원시 응답을 저장하도록 했다. 요청 언어와 응답 언어에 같은 이름을 쓰면 나중에 어느 쪽 값인지 혼동하기 쉽다.

다음은 값의 종류를 보여주는 기록 형식 제안이다. 실제 호출 기록이나 완성된 저장 스키마는 아니다.

input.audio_sha: 입력 파일의 지문
input.model_id: 요청 모델
input.language_code: 요청 언어 또는 자동 감지
input.options: 실제로 보낸 추가 옵션
response.language_code: 응답이 알려준 언어
response.language_probability: 응답에 있을 때 보존
response.raw: 접근 범위를 제한한 원시 응답
cache.reused: 이번 검사에서 재사용했는지
run.checked_at: 언제 어떤 입력을 확인했는지

원시 응답은 다음 조사에 도움이 되지만 음성 내용이나 개인정보를 포함할 수 있다. 공개 글에 그대로 붙이는 자료와 내부 진단 자료를 구분하고, 필요 범위·접근 권한·보존 기간을 정한다. 모델 이름이 같아도 제공자의 내부 버전이 바뀔 수 있으므로 영구 재사용을 보장하는 키로 취급하지 않는다. 재검사가 필요한 시점과 강제 무효화 방법도 별도 정책으로 둔다.

재전사와 음성 수선을 한 결과로 합치지 않는다

10월 2일 인계 기록은 이전 불량 결과에 응답 언어가 남아 있지 않아 자동 감지 문제와 옛 캐시 문제를 확정할 수 없었다고 적는다. 같은 음성의 재전사에서도 이름·시각 발음 문제가 확인됐고, 이후 발음 표기를 조정한 음성 재생성과 재전사를 진행했다고 기록한다.

이를 “캐시를 고쳐 발음을 해결했다”로 요약하면 중간 단계가 사라진다. 캐시 수정은 현재 요청으로 다시 검사할 출발점을 만들고, 음성 재생성은 검사 대상 자체를 바꾸는 작업이다.

시도 고정한 것 바꾼 것 다음에 비교할 것
재전사 같은 음성 파일 모델·언어·재사용 여부 요청 입력과 새 응답
음성 수선 목표 대사와 검수 기준 발음 표기·생성 음성 새 파일 지문과 실제 소리
수선 후 확인 새 음성 필요 시 전사 실행 대본·이름·실제 발음의 일치

이 표는 다음 작업에서 변수를 나누기 위한 틀이다. 당시 모든 원시 비교 로그를 이번에 재실행했다는 뜻은 아니다. 결과가 나아졌더라도 무엇을 바꾼 시도였는지 분리해 적어야 캐시, 전사 모델, 음성 생성 중 어디를 다시 볼지 알 수 있다.

다음 재검사에서 확인할 순서

먼저 입력 파일의 지문과 요청 조건을 저장 기록 옆에 놓는다. 재사용됐다면 어떤 조건이 같아서 허용됐는지 확인한다. 새 요청이 필요하면 해당 기록을 정책에 따라 무효화하고 실행 결과를 별도 보존한다. 마지막으로 대본과 실제 음성을 대조한다.

환경 자체가 재현되지 않는 문제는 빈 클론 인계 점검의 범위다. 여기서는 실행 환경 안에서 얻은 결과가 지금 검사하려는 입력을 가리키는지를 먼저 확인한다.

세 줄 요약

  • 캐시 입력에는 음성 파일뿐 아니라 실제 요청에 사용한 모델·언어·추가 옵션을 반영한다.
  • 재사용 조건 통과는 전사 품질 통과가 아니므로 요청·응답·품질 검사를 별도로 기록한다.
  • 재전사와 음성 재생성은 바꾸는 대상이 다르며 발음 개선은 별도의 음성 검수로 확인한다.

같이 읽을 글

  • set -e 스크립트가 에러 없이 중간에 끝날 때: 변수에 담은 grep 한 줄 찾기

    set -e를 켠 bash 검사 스크립트가 통과해야 할 때만 아무 메시지 없이 멈췄다. macOS bash 3.2·zsh·sh로 원인(grep의 매치 없음 종료 코드 1)과 세 가지 수정, 수정이 삼키는 오류를 재현했다.

  • macOS에서 grep -P가 안 될 때: 오류가 나는 경우와 조용히 비거나 엉뚱한 결과가 나오는 경우

    macOS 기본 grep에서 grep: invalid option -- P 가 나올 때 대체 방법과, 오류 없이 비거나 엉뚱한 결과가 나오는 \d+·\K 같은 정규식을 이 맥에서 직접 실행해 가려냈다.

  • SwiftUI 공유 시트가 비어 있을 때: item으로 공유 데이터 함께 넘기기

    첫 공유가 빈 시트인 경우를 자체 예제로 대조하고, 선택한 문자열과 Copy 출력까지 확인하는 item 기반 구현을 제공한다.
