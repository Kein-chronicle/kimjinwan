덱빌딩 카드가 사라지거나 중복될 때: 상태 원장과 통합 플레이 검사

기록일 2026. 5. 20.수정 2026. 10. 13.

표시 날짜는 기존 덱 설계의 대표일입니다. 2026년 10월 14일 설계·통합 커밋을 확인하고 참조 모델을 실행해 06·07·08을 통합했습니다.

이 글의 목적

덱빌딩 개발자가 카드 선택과 변형 때 누락·중복을 찾고 로비부터 결산까지 통합 검사 범위를 정한다.

핵심 내용

장수 합계만으로는 중복과 누락을 놓친다. 카드 ID를 다섯 위치에서 대조하고 새 카드 생성 이력과 실제 플레이 경로를 함께 검사한다.

읽고 나서

카드 종류가 같은 사본에도 ID를 붙이고 한 번의 선택 전후 다섯 위치를 기록한다.

  • 세 줄 요약

한 줄 요약: 덱 규칙은 카드 ID와 다섯 위치의 이동으로 검사하고, 브랜치 병합 뒤에는 선택→전투→결산까지 같은 데이터가 이어지는지 확인한다.

카드 선택 화면이 닫혔다고 선택이 올바르게 반영된 것은 아니다. 고르지 않은 카드가 사라지거나, 변형 전 무기가 다음 드로우에 다시 나타날 수 있다. 이 글은 카드의 위치 원장과 짧은 통합 플레이 경로를 함께 사용하는 점검법을 제안한다.

웨일서바이버의 물리 카드 설계 문서와 2026년 8월 7일 실행 복구 커밋을 10월 14일 원격에서 다시 읽었다. 별도로 작은 Python 참조 모델을 작성해 네 가지 검사를 실행했다. 참조 모델의 통과는 현재 게임 구현이나 실제 플레이의 통과를 뜻하지 않는다.

카드 종류와 카드 한 장의 ID를 구분한다

원래 설계 문서는 런 덱을 카드 종류 목록이 아니라 여러 사본이 있는 카드 더미로 정의한다. 당시 예시는 무기 카드 10종이 각각 최대 레벨 6만큼 사본을 제공하고, 처음 장착한 고유 무기 1장을 이미 소비했으므로 뽑을 더미에 59장이 남는 구조다. 59장은 당시 문서의 예시이며 현재 모든 덱의 고정 장수가 아니다.

같은 무기의 사본도 base-1, base-2처럼 개별 ID를 주면 어느 장이 어디로 갔는지 추적할 수 있다. 화면에 보이는 종류 이름만 비교하면 같은 종류의 카드 한 장이 중복되고 다른 한 장이 사라진 문제를 놓칠 수 있다.

위치 뜻 이동이 일어나는 때
뽑을 더미 아직 선택지로 나오지 않은 카드 드로우, 새 카드 추가
현재 선택지 뽑았지만 아직 결정을 기다리는 카드 카드 선택·선택 취소 정책
버림패 뽑혔지만 선택하지 않은 카드 재섞기
장착·소비 이력 선택해 빌드에 반영한 카드 변형 등으로 효과 제거
제거 이력 다시 뽑히지 않도록 뺀 카드 원인 추적용으로 보존

이 표는 검증용 원장 분류다. 게임의 실제 자료구조 이름과 같을 필요는 없다. 원래 문서는 선택한 카드를 빌드에 소비하고 고르지 않은 카드를 버림패로 보낸다고 정한다. 따라서 뽑을 더미·선택지·버림패·제거만 합치면 이미 선택한 카드가 빠진다.

장수 합계와 ID 유일성을 함께 검사한다

검증용 원장에서는 삭제된 카드도 제거 이력에 남긴다고 정하자. 그때 다섯 위치의 장수 합은 시작 장수 + 새로 만든 카드 수와 맞아야 한다. 기존 카드를 완전히 기록에서 지우는 정책이면 별도 삭제 원장도 식에 포함해야 한다.

장수가 맞는 것만으로 충분하지 않다. 아래 함수는 카드가 두 위치에 동시에 있지 않은지, 등록한 ID가 전부 존재하는지도 확인한다. zones는 위 다섯 위치의 카드 목록이고 registry는 시작 카드와 이후 생성한 카드 ID의 집합이다.

def audit(zones, registry):
    ids = [c["id"] for cards in zones.values() for c in cards]
    assert len(ids) == len(set(ids)), "중복 카드 ID"
    assert set(ids) == registry, "누락 또는 등록 안 된 카드 ID"
    return {name: len(cards) for name, cards in zones.items()}

한 장을 복제하고 다른 한 장을 지우면 전체 장수는 그대로다. 유일성 검사와 등록 ID 대조가 이 오류를 잡는다. 실제 게임에서는 추가로 카드 종류·레벨·효과의 대응도 검사해야 한다. 위 함수가 공격력이나 재미를 검증해 주지는 않는다.

여섯 장 예시에서 선택과 재섞기를 본다

작성한 참조 모델은 처음에 같은 무기의 사본 여섯 장을 뽑을 더미에 넣는다. 세 장을 뽑아 하나를 선택하면 나머지 두 장은 버림패로 간다. 다음 세 장에서도 하나를 선택한 뒤 버림패를 다시 뽑을 더미로 옮겼다. 재섞기의 순서 무작위성은 이번 검사 범위에 넣지 않았다.

실행한 검사 뽑을 더미 선택지 버림패 장착·소비 제거 관찰 결과
6장에서 3장 뽑고 1장 선택 3 0 2 1 0 ID 보존·유일성 통과
남은 3장에서도 1장 선택 후 버림패 이동 4 0 0 2 0 ID 보존·유일성 통과
기본 무기 레벨 3에서 변형 5 0 0 1 6 기본 카드가 활성 위치에 없음
장수는 유지하며 ID 한 장을 복제 — — — — — 중복 ID를 검출해 거부

네 검사는 2026년 10월 14일 Python 참조 모델에서 실행한 결과다. 실제 게임의 랜덤 드로우·저장 복구·렌더러를 호출한 것은 아니다. 정상 사례만으로는 결함을 잡는지 알기 어려워 마지막에는 의도적으로 중복을 넣었다.

변형 카드가 선택되면 세 곳 이상을 지운다

물리 카드 설계는 무기 변형을 선택할 때 기본 무기의 카드를 뽑을 더미·버림패·현재 선택지에서 제거하고, 이미 선택한 기본 레벨도 제거된 것으로 취급한다. 변형 무기는 레벨 1로 들어가고 남은 사본 다섯 장이 더미에 추가된다.

참조 모델에서는 기본 카드 여섯 장 중 세 장이 장착 이력에, 나머지 세 장이 뽑을 더미·버림패·선택지에 한 장씩 있다고 놓았다. 변형 카드 한 장도 선택지에 있다. 변형을 선택하면 기본 여섯 장은 모두 제거 이력으로 옮기고 변형 카드의 기존 ID를 유지한 채 장착 위치로 옮겼다. 새 변형 사본 다섯 장은 새 ID로 등록했다.

따라서 이 원장의 총수는 시작 7장에 새로 만든 5장을 더한 12장이다. 변형 카드 ID를 재사용하는 것은 이번 참조 모델의 회계 규칙이다. 실제 구현이 변형 카드를 제거하고 레벨 1 카드를 새로 만들면 생성·제거 이력도 그 방식에 맞춰 달라진다. 중요한 검사는 다음 드로우 후보와 현재 효과에 기본 무기가 남지 않는지다.

변형 뒤에도 예전 카드가 보이면 뽑을 더미만 지웠는지, 현재 선택지와 버림패를 빠뜨렸는지부터 확인한다. 같은 입력 사건이 두 번 처리됐을 때 사본 다섯 장이 두 번 추가되지 않는지도 별도 회귀 사례로 둔다. 중복 사건 처리는 이번 네 검사에는 포함하지 않았다.

병합 뒤에는 화면이 아니라 데이터의 경로를 잇는다

8월 7일 7c589205에는 덱 준비 화면·전투 화면·렌더러·무기 코드 변경과 자산 예산·콘텐츠 무결성·런타임 스모크 검사가 함께 들어 있다. 실제 스모크 스크립트는 로비에서 드래프트를 거쳐 전투에 진입하고 이동·대시·일시 정지와 복귀를 시도한다. 그 스크립트의 범위에는 결산과 다음 런 저장 확인이 없다. 이번 확인은 코드 읽기이며 당시 시험을 재실행한 결과가 아니다.

기존 기능이 연결됐는지 보려면 다음과 같이 범위를 더 구체적으로 정할 수 있다. 아래는 추가할 통합 점검 제안이다.

경로 데이터 검사 처음 하는 플레이어에게 보여줄 설명
로비→덱 선택 고른 카드 ID와 허용 수, 잠긴 카드 제외 지금 몇 장을 고를 수 있는가
선택→전투 진입 선택한 ID·레벨이 전투 빌드에 반영 선택이 어떤 공격으로 이어지는가
드로우→변형 다섯 위치와 카드 종류·효과 정합성 기본 무기가 무엇으로 교체되는가
전투 종료→결산 승패·획득·소비가 결과에 일치 이번에 얻은 것과 사라진 것
결산→다음 런 저장 후 재진입 값과 해금 조건 다음 판에 유지되는 것

태그나 메타 성장을 추가할 때도 내부 필드명만 정리하지 말고, 플레이어가 그 순간 결정해야 할 내용을 붙인다. 모든 규칙을 첫 화면에 나열하기보다 선택할 때 필요한 설명을 해당 위치에 둔다. 이 제안의 효과는 실제 독자·플레이어 관찰로 확인해야 하며 과거 화면 한 장이 그 결과를 대신하지 않는다.

카드 원장 검사는 상태의 정합성을, 통합 경로는 화면·전투·저장의 연결을 다룬다. 둘이 통과해도 밸런스나 재미 평가는 남는다. 이미지 누락과 파일·프레임 수 문제는 게임 이미지 검수와 용량 감사의 원장으로 별도 확인한다.

세 줄 요약

  • 선택한 카드 이력까지 다섯 위치에 포함하고, 장수 합계와 ID 유일성을 함께 검사한다.
  • 변형할 때 뽑을 더미·버림패·선택지·기존 장착 효과를 함께 정리하고 새 카드 생성을 기록한다.
  • Git 병합과 짧은 스모크 통과를 구분하며, 결산·저장까지 이어지는 범위를 별도로 검증한다.
