빈 클론 개발 인계: 패키지·OS 도구·개인 입력·미검증을 나누는 법

기록일 2026. 10. 1.수정 2026. 10. 13.

2026년 10월 14일 원본 코드와 기록을 다시 확인해 보강했습니다. 당시 실행과 이번 검사·제안은 본문에서 구분합니다.

이 글의 목적

개발인계를받는사람이새환경의시작조건과빠진검증을정확히알수있게한다.

핵심 내용

빈클론은전역도구까지비우지않는다.패키지·OS도구·개인입력·검증범위를분리하고누락검사는미검증으로남긴다.

읽고 나서

기준커밋·환경·실행명령과검사별통과실패미검증을한인계표에작성한다.

목차
  • 빈 클론이 비우는 것과 비우지 않는 것
  • 실제 기록이 고친 네 가지
  • 설치 성공과 시작 가능을 나눠 검사한다
  • 개인 입력이 없을 때의 결과는 미검증이다
  • 인계 완료 문장에는 다음 시작점을 넣는다
  • 세 줄 요약

한 줄 요약: 빈 클론 인계는 저장소·패키지·운영체제 도구·개인 입력·검증 범위를 나눠 확인하고, 빠진 검사를 통과로 바꾸지 않은 실행 기록을 남기는 작업이다.

기존 폴더에서는 시험이 통과한다. 그런데 새 작업자는 첫 명령부터 멈춘다. 옆 저장소의 패키지, 이미 만들어둔 가상환경, 개인 녹화본, 운영체제 도구가 원래 컴퓨터에만 있었기 때문이다. 인계 문서가 길어도 이 시작 조건이 빠지면 재개하기 어렵다.

영상 편집 도구의 2026년 10월 1일 커밋 536b208과 보관 문서를 다시 읽어, 새 환경에서 무엇을 확인할지 정리했다. 문서에는 당시 빈 클론의 검사와 25개 시험 통과가 기록돼 있다. 이번 글을 위해 새 컴퓨터에서 그 25개를 재실행한 것은 아니다.

빈 클론이 비우는 것과 비우지 않는 것

새 폴더에 저장소를 받으면 기존 작업 폴더의 미추적 파일과 설치 폴더를 그대로 가져오지 않게 할 수 있다. 하지만 같은 컴퓨터의 전역 도구, 환경변수, 인증 상태, 홈 폴더 설정까지 사라지지는 않는다.

따라서 같은 컴퓨터의 새 클론은 출발점이지 다른 운영체제의 재현 성공과 같지 않다. “새 폴더에서 성공”과 “새 기기에서 성공”을 보고서의 다른 칸에 둔다.

의존 종류 확인할 질문 남길 증거
저장소 필요한 코드·문서가 해당 커밋에 있는가? 커밋 ID와 작업트리 상태
프로젝트 패키지 선언·잠금 파일로 설치되는가? 설치 명령·버전·종료 코드
OS 도구 미디어 처리기·브라우저·컴파일러가 필요한가? 탐색 결과·경로·버전
개인 입력 저장소 밖 파일이나 권한이 필요한가? 필요한 자료 종류와 관련 검사
결과 범위 실행·실패·미실행 항목은 무엇인가? 검사별 로그와 남은 조건

패키지 경계 자체는 이웃 저장소 의존성 글에서 다룬다. 여기서는 그 밖의 도구·입력·운영체제 조건까지 인계 범위에 넣는다.

실제 기록이 고친 네 가지

당시 기록과 코드 변경은 다음 항목을 보여준다.

막히던 조건 기록된 변경 여전히 따로 확인할 것
다른 저장소의 Playwright 경로 사용 자체 개발 의존성과 일반 패키지 이름으로 변경 잠금 파일대로 설치된 패키지 해석
개인 아이폰 녹화본의 고정 경로 REAL_HEVC 환경변수로 받음 실제 입력이 있을 때 해당 영상 검사
개발 문서의 개인 절대경로 클론 폴더 기준 시작과 선행 도구 표 사용하는 셸·도구 버전
가상환경 누락과 단일 Chrome 경로 가상환경 진단, 여러 OS의 Chrome 후보 경로 추가 실제 대상 OS에서 탐색·실행되는지

마지막 행을 “모든 OS 지원”으로 읽으면 안 된다. 보관 진단 코드의 가상환경 경로는 .venv/bin/python이고, Chrome도 정해진 후보 경로를 찾는다. 모든 설치 위치나 Windows의 Python 환경까지 검증하는 범용 탐색기는 아니다.

Swift/AVFoundation 검사는 macOS 전용으로 문서에 구분돼 있다. 진단 스크립트는 누락 도구가 있으면 종료 코드 1을 내므로, 다른 OS에서 Swift가 없다는 사실을 숨기고 전체 초록으로 보고해서는 안 된다. 어떤 작업을 계속할 수 있고 어떤 계약은 미검증인지 항목별로 판단해야 한다.

설치 성공과 시작 가능을 나눠 검사한다

npm의 npm ci 문서는 잠금 파일이 필요하고 패키지 선언과 어긋나면 오류로 멈추며, 기존 node_modules가 있으면 제거한 뒤 설치한다고 설명한다. 잠금 파일 생성에 사용한 의존성 관련 옵션도 맞춰야 한다.

이 명령은 프로젝트 패키지 설치를 검사하는 단계다. Python 가상환경, ffmpeg, 개인 녹화본까지 준비됐다는 뜻은 아니다. 아래 순서는 특정 프로젝트의 명령을 무조건 복사하는 설치 스크립트가 아니라 인계 실행표의 구조다.

  1. 확인할 커밋과 대상 OS·도구 버전을 적는다.
  2. 별도 폴더에 저장소를 받고 문서에 적힌 패키지 설치를 실행한다.
  3. 문서의 OS 도구·가상환경·브라우저 진단을 실행한다.
  4. 저장소만으로 실행 가능한 검사를 먼저 실행한다.
  5. 개인 입력·외부 권한이 필요한 검사는 조건 충족 여부를 따로 기록한다.
  6. 실제 시작 화면 또는 최소 작업 경로를 실행하고 종료 방법도 확인한다.

기존 폴더의 설치 디렉터리를 연결하거나 개인 파일을 몰래 복사해 성공시키면 빠진 시작 조건을 찾기 어렵다. 필요한 항목이면 설치·제공 경로를 문서에 명시하고 다시 확인한다.

개인 입력이 없을 때의 결과는 미검증이다

보관된 미디어 생성 스크립트는 REAL_HEVC가 없으면 실기기 HEVC 항목을 건너뛰며 미검증이라고 출력한다. 합성 미디어는 별도로 생성한다. 그 합성 자료로 통과한 검사가 실제 아이폰 녹화본의 가변 프레임레이트 문제까지 확인한 것은 아니다.

다음은 인계 보고서에 사용할 가상 기록 예시다. 이번 프로젝트의 새 실행 결과가 아니다.

항목 상태 이유·다음 행동
패키지 설치 통과 잠금 파일과 선언 일치, 설치 로그 첨부
합성 입력의 기능 검사 통과 지정한 입력·경로만 확인
실기기 녹화본 검사 미검증 입력 미제공, 자료 확보 뒤 해당 명령 재실행
OS 전용 교차검증 미검증 현재 OS 미지원, 대상 OS 담당자 지정
브라우저 시작 실패 필요한 브라우저 실행 파일 없음, 설치 후 재검사

종료 코드와 이 표를 함께 남긴다. 프로세스가 정상 종료했어도 일부 검사가 건너뛰어졌을 수 있다. 반대로 진단이 실패했더라도 원인이 특정 도구 부재라면 관련 없는 작업과 분리할 수 있다. 어느 경우든 전체 인계 완료라고 한 단어로 덮지 않는다.

인계 완료 문장에는 다음 시작점을 넣는다

“문서 정리 완료” 대신 다음처럼 범위를 쓴다.

기준 커밋: <식별값>
확인 환경: <OS·런타임·필수 도구 버전>
재개 명령: <문서에서 실제 실행한 순서>
통과: <검사 이름과 로그>
미검증: <없는 입력·전용 OS·외부 권한>
실패: <재현 명령과 오류>
다음 행동: <누가 무엇을 확보해 어떤 명령을 다시 실행할지>

10월 1일의 25개 시험 통과는 당시 환경의 기록으로 보존한다. 오늘의 제품 기능 수나 다른 영상 형식의 성능 검증으로 확장하지 않는다. 새 검증을 했다면 날짜·커밋·환경이 붙은 새 기록을 만든다.

좋은 인계의 결과는 모든 칸이 초록인 표만은 아니다. 다음 작업자가 무엇을 바로 실행할 수 있고 어떤 조건이 빠졌는지 정확히 아는 상태도 필요하다. 그 경계를 문서와 실제 명령 결과가 함께 설명해야 한다.

세 줄 요약

  • 새 폴더의 클론은 전역 도구와 인증까지 비우지 않으므로 확인 환경을 별도로 기록한다.
  • 패키지·OS 도구·개인 입력을 나누고 없는 입력의 검사를 합성 자료의 통과로 대체하지 않는다.
  • 인계에는 커밋·실행 순서·통과·실패·미검증과 다음 재검사 조건을 함께 남긴다.

같이 읽을 글

  • set -e 스크립트가 에러 없이 중간에 끝날 때: 변수에 담은 grep 한 줄 찾기

    set -e를 켠 bash 검사 스크립트가 통과해야 할 때만 아무 메시지 없이 멈췄다. macOS bash 3.2·zsh·sh로 원인(grep의 매치 없음 종료 코드 1)과 세 가지 수정, 수정이 삼키는 오류를 재현했다.

  • SwiftUI 공유 시트가 비어 있을 때: item으로 공유 데이터 함께 넘기기

    첫 공유가 빈 시트인 경우를 자체 예제로 대조하고, 선택한 문자열과 Copy 출력까지 확인하는 item 기반 구현을 제공한다.

  • SwiftUI 숫자패드 닫기: 두 입력칸의 포커스를 nil로 해제하기

    numberPad·decimalPad 화면에 Done 버튼을 추가하고, 두 입력칸에서 버튼 한 개·키보드 닫힘·입력값 보존을 확인하는 최소 예제를 제공한다.
