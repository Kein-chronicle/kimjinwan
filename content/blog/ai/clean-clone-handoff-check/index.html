AI 활용기: 개발 인계 문서가 있어도 빈 클론에서 시작해 봐야 하는 이유

발행 2026. 10. 1.
이 글의 목적

AI에게 개발 인계를 맡기는 사람이 문서의 양보다 새 작업 환경에서 재개 가능한지를 확인하게 한다.

핵심 내용

10월 1일 영상 편집 도구 작업 기록은 빈 클론 검증으로 개인 녹화본 경로, 가상환경 부재, 운영체제별 브라우저 탐색 문제를 고쳤다고 남겼다. 기존 컴퓨터의 테스트 통과만으로는 새 환경의 시작 조건을 확인할 수 없다.

읽고 나서

새 폴더에 저장소를 클론해 문서 순서대로 설치·환경 진단·검사를 실행하고, 없는 개인 자료는 미검증으로 명시한다.

목차
  • 먼저 답하면
  • 오늘 작업 기록에서 확인한 것
  • 공식 문서와 연결하면
  • 다음 인계에서 남길 것

먼저 답하면

AI가 인계 문서를 정리했어도 새 폴더의 빈 클론에서 그 순서대로 시작할 수 있는지 확인해야 한다. 기존 컴퓨터에는 문서에 없는 파일과 설치 상태가 남아 있기 때문이다. 10월 1일 개인 영상 편집 도구의 실제 작업 기록에서도, 인계 준비 중 이 문제가 드러났다.

오늘 작업 기록에서 확인한 것

해당 커밋은 빈 클론에서 작업 재개를 실측하고 네 가지 환경 의존을 고쳤다고 기록한다. 이웃 저장소에서 빌려 쓰던 테스트 패키지를 자체 의존성으로 선언한 것 외에도, 개인 녹화본의 고정 경로를 환경변수로 받게 했고, 실행 문서를 클론 폴더 기준으로 바꿨다. 환경 진단에는 가상환경 부재 알림과 운영체제별 Chrome 탐색을 넣었다.

개인 녹화본이 없으면 해당 검증만 미검증으로 남기는 점이 특히 유용했다. 누구나 받을 수 있는 저장소와 개인 자료를 분리하되, 빠진 자료가 필요한 시험을 통과했다고 쓰지 않는 방식이다.

기록에는 새 클론에서 설치·가상환경 준비·환경 진단·검사와 25개 테스트를 확인했다고 남아 있다. 이것은 당시 작업의 검증 기록이며, 이 글을 쓰면서 다른 컴퓨터에서 다시 실행한 결과는 아니다. 새 환경에서 모든 영상 형식이나 성능까지 확인했다는 뜻도 아니다.

공식 문서와 연결하면

npm의 npm ci 문서는 잠금 파일을 사용해 설치하고, 패키지 선언과 잠금 파일이 다르면 오류로 멈추는 절차를 설명한다. 설치 상태가 남아 있던 작업 폴더보다 의존성 재현 여부를 확인하기 좋다. 다만 OS 도구나 개인 입력 파일까지 설치해 주는 기능은 아니다.

Twelve-Factor의 개발·운영 환경 일치 원칙은 환경의 도구 차이가 장애를 만들 수 있으므로 차이를 줄이라고 설명한다. 서버 운영에 관한 원칙을 이번 개발 인계에 그대로 적용한 규칙이라고 주장하지는 않는다. 문서 밖 환경 차이를 줄여야 한다는 방향을 참고했다.

다음 인계에서 남길 것

새 폴더에 클론한 뒤 문서 순서로 설치와 환경 진단을 실행한다. 그 결과에는 필수 도구, 개인 자료가 필요한 시험, 아직 확인하지 못한 환경을 나눠 적는다. 기존의 이웃 저장소 의존성 사례가 패키지 경계를 다뤘다면, 이번 점검은 그 밖의 시작 조건도 포함한다. 인계 완료 기준은 문서 개수가 아니라, 다음 작업자가 어디서 시작하고 무엇이 빠졌는지 확인할 수 있는 상태다.

같이 읽을 글

  • set -e 스크립트가 에러 없이 중간에 끝날 때: 변수에 담은 grep 한 줄 찾기

    set -e를 켠 bash 검사 스크립트가 통과해야 할 때만 아무 메시지 없이 멈췄다. macOS bash 3.2·zsh·sh로 원인(grep의 매치 없음 종료 코드 1)과 세 가지 수정, 수정이 삼키는 오류를 재현했다.

  • SwiftUI 공유 시트가 비어 있을 때: item으로 공유 데이터 함께 넘기기

    첫 공유가 빈 시트인 경우를 자체 예제로 대조하고, 선택한 문자열과 Copy 출력까지 확인하는 item 기반 구현을 제공한다.

  • SwiftUI 숫자패드 닫기: 두 입력칸의 포커스를 nil로 해제하기

    numberPad·decimalPad 화면에 Done 버튼을 추가하고, 두 입력칸에서 버튼 한 개·키보드 닫힘·입력값 보존을 확인하는 최소 예제를 제공한다.
