텍스트 비교기 — 수정한 한 줄이 삭제와 추가로 나오는 이유

발행 2026. 10. 2.
이 글의 목적

문서 수정 이력을 살피는 독자가 줄 단위 차이와 실제 내용 변경을 구분하도록 돕는다.

핵심 내용

한 줄의 일부만 수정해도 줄 단위 비교에서는 원래 줄 삭제와 새 줄 추가로 나온다. 추가·삭제 줄 수를 바뀐 글자 수나 의미 변화량으로 해석하지 않는다.

읽고 나서

수정 전후 텍스트를 붙여 넣고 양쪽 줄 번호와 차이가 난 줄의 본문을 함께 확인한다.

목차
  • 먼저 답하면
  • 비교하는 순서
  • 공백 무시를 켜면 무엇이 달라질까
  • 결과를 복사하기 전에

먼저 답하면

회의: 월요일 10시를 회의: 화요일 14시로 고치면 삭제 1줄과 추가 1줄로 표시된다. 텍스트 비교기는 글자별 수정 표시가 아니라 줄 단위 비교를 한다. 따라서 삭제 수와 추가 수를 더한 값이 수정한 문장 수나 바뀐 글자 수는 아니다. 양쪽 줄 번호와 해당 줄의 내용을 함께 읽어야 실제 변경을 판단할 수 있다.

비교하는 순서

왼쪽에 수정 전, 오른쪽에 수정 후 텍스트를 붙여 넣는다. 추가된 줄은 수정본 줄 번호, 삭제된 줄은 원본 줄 번호와 함께 나오며, 유지된 줄은 양쪽 번호가 함께 표시된다. 중간에 한 줄을 넣으면 뒤의 줄 번호가 달라져도 내용이 같으면 유지로 대응된다. 빈 입력과 내용이 있는 입력을 비교하면 모든 줄이 추가 또는 삭제로 나온다.

예를 들어 원본이 준비물: 노트북과 장소: 3층 두 줄이고, 수정본 앞에 온라인 참석 가능을 한 줄 추가했다면 새 줄만 추가로 표시된다. 기존 두 줄은 원본 1·2번과 수정본 2·3번으로 대응된다. 동일한 문장이 여러 번 반복된 문서에서는 대응 방식이 사람이 의도한 구획과 다를 수 있으므로 주변 문맥도 살펴야 한다.

공백 무시를 켜면 무엇이 달라질까

이 옵션은 각 줄의 스페이스와 탭을 제거한 값으로 줄이 같은지 판단한다. 이름: 민지와 이름:민지는 유지로 간주될 수 있다. 줄바꿈 자체를 제거하거나 모든 종류의 유니코드 공백을 무시하는 옵션은 아니다. 코드 들여쓰기나 단어 사이의 간격이 의미를 갖는 자료에서는 옵션을 끄고 비교하는 편이 적절하다.

윈도우 CRLF와 일반 LF 같은 줄바꿈 형식은 동일하게 취급한다. 다만 마지막에 줄바꿈이 붙어 생긴 빈 줄은 비교 대상에 포함될 수 있다. 보이지 않는 끝줄 차이가 나오면 문서 마지막 줄도 확인한다.

결과를 복사하기 전에

각 입력은 최대 100,000자·500줄이다. 이를 넘는 자료는 공통 소제목이나 문단 경계를 기준으로 양쪽을 같은 구간으로 나누어 비교한다. 한쪽만 임의로 자르면 실제 수정과 무관한 대량 삭제·추가가 나온다.

복사 결과의 +는 추가, -는 삭제, 앞의 공백은 유지 줄을 뜻한다. 파일에 바로 적용하는 패치 형식이나 병합 결과는 아니므로 원본 파일을 덮어쓰는 입력으로 사용하지 않는다. 입력과 비교는 브라우저 안에서 처리하지만, 클립보드 내용을 다른 서비스에 붙여 넣을 때는 공유 범위를 다시 확인한다.

변경 전후 길이만 확인하려면 글자 수·읽기 시간 계산기를 함께 사용할 수 있다. 의미가 같은 표현인지, 일정·수치가 올바른지는 이 비교기의 추가·삭제 표시만으로 판정할 수 없다.

같이 읽을 글

  • JSON 포매터·검증기 — 큰 숫자는 그대로 두고 공백만 정리하기

    API 응답과 설정 JSON을 2칸·4칸 또는 한 줄로 정리한다. 큰 정수와 숫자 표기를 보존하는 방식, 중복 키 오류, 문법 검사와 데이터 검증의 차이를 설명한다.

  • 중복 줄 제거기 — 공백 무시를 켜도 원문이 그대로 남는 이유

    한 줄씩 입력한 목록에서 중복을 정리하고 첫 등장 순서와 원문 줄 번호를 확인한다. 공백·대소문자 비교 옵션이 결과를 바꾸는 범위와 빈 줄 처리의 차이를 설명한다.

  • CSV와 JSON 변환 — 따옴표 안의 쉼표가 열을 늘리지 않게 하려면

    CSV 첫 행을 열 이름으로 읽어 JSON 객체 배열로 바꾸거나, 평평한 JSON 객체 배열을 CSV로 바꾼다. 따옴표 안의 쉼표·줄바꿈과 누락 값을 어떻게 처리하는지 예시로 확인한다.
