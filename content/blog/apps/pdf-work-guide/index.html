PDF 합치기·나누기·압축·서명 실무: 작업 순서와 지켜야 할 한계

발행 2026. 10. 14.
이 글의 목적

서류용 PDF를 만들거나 줄일 때 어떤 작업을 어떤 순서로 해야 글자와 서명이 망가지지 않는지 스스로 정하게 돕는다.

핵심 내용

합치기·나누기·정리는 페이지를 복사해 글자가 유지되고, 압축과 이미지 변환은 페이지를 이미지로 바꿔 글자·링크·서명 정보가 사라진다. 압축은 글자 검색을 없애므로 필요할 때만 쓰고 서명은 그 뒤에 넣으며, 원본은 따로 보관한다.

읽고 나서

먼저 쓸 PDF의 쪽수와 용량을 확인하고, 제출처의 용량 제한에 맞춰 이 글의 작업 순서대로 진행한다.

한 줄 요약: PDF 작업은 페이지를 그대로 복사하는 것(합치기·나누기·정리)과 이미지로 다시 만드는 것(압축·이미지 변환)으로 갈리므로, 압축은 글자 검색을 없애므로 필요할 때만 쓰고, 서명은 압축 뒤에 넣고 원본은 따로 남기면 된다.

신청서와 증빙 스캔본을 한 파일로 모았더니 용량 제한에 걸리고, 줄였더니 글자를 드래그할 수 없게 된 경험이 이 글의 출발점이다. 여기서는 PDF 작업 일곱 가지를 하나의 기준(원본 페이지를 복사하는가, 이미지로 다시 만드는가)으로 묶고, 제출용 PDF를 만드는 순서와 각 작업의 한도를 표로 정리한다. 한도와 동작은 이 사이트의 PDF 도구 소개와 도구 소스를 2026년 10월 14일에 확인한 값이며, 디지털 서명의 일반 개념은 아래 출처의 설명을 따른다.

먼저 용어. 벡터는 글자와 선을 수식으로 저장해 확대해도 선명한 방식이고, 래스터는 점(픽셀)으로 저장해 확대하면 흐려지는 방식이다. 스캔본은 종이를 사진처럼 찍은 래스터 이미지가 대부분이다. 디지털 서명은 인증서로 서명자와 문서 변경 여부를 확인하는 암호 기반 서명이고, 서명 이미지는 손글씨 사진을 문서에 붙인 그림일 뿐이다. 둘은 다르다.

기준 하나: 복사하는 작업과 다시 만드는 작업

작업 하는 일 글자 선택·검색 한도
합치기 여러 PDF의 원본 페이지를 복사해 한 파일로 유지 1–20개, 전체 100MB
나누기·추출 고른 페이지를 새 파일로(또는 쪽마다 ZIP) 유지 범위는 1-3, 5, 8-10 형식
페이지 정리 번호 순서대로 재배열·일부만 추출 유지 3, 1, 2처럼 번호를 하나씩
압축 각 페이지를 JPEG 이미지로 다시 만듦 사라짐 50MB 이하, 20페이지 이하
PDF JPG·PNG 변환 페이지를 JPG·PNG로 저장 이미지에는 없음 30페이지, 배율 1–3배
이미지 PDF 변환 사진을 A4 한 쪽씩 해당 없음 30장, 긴 변 2,400px로 축소
서명·워터마크 원본 PDF를 불러와 선택한 페이지 위에 이미지·문구 그리기 본문 유지(도구 소스 확인) 서명은 PNG·JPG

합치기는 소개 문서에 원본 페이지를 이미지로 다시 만들지 않고 그대로 복사하므로 글자 선택·검색과 벡터 품질이 유지된다고 적혀 있고, 나누기도 원본 페이지를 이미지로 바꾸지 않아 글자 검색이 유지된다고 적혀 있다. 반대로 압축은 각 페이지를 이미지(JPEG)로 다시 만드는 방식이라 텍스트 선택·검색, 링크, 입력 양식, 전자서명 정보가 사라진다고 밝힌다. 그래서 같은 20쪽 문서라도 합치기를 거친 파일과 압축을 거친 파일은 쓸모가 다르다. 압축본은 보내기에는 가볍지만 내용을 복사하거나 검색할 수 없고, 서명 완료본에는 맞지 않는다.

복사하는 작업에도 주의가 하나 있다. 합치기 소개는 링크나 입력 양식이 합친 파일에서 다르게 동작할 수 있다고, 나누기와 페이지 정리 소개는 전자서명과 입력 양식이 페이지 복사 과정에서 달라질 수 있다고 안내한다. 결과 파일을 열어 확인해야 한다. 합치기·나누기·정리·압축·서명·워터마크 도구는 암호가 없고 손상되지 않은 PDF만 받으므로 암호는 먼저 해제한다.

압축 단계가 실제로 하는 일

압축 도구의 세 단계는 JPEG 품질과 긴 변 기준이 다르다. 도구 소스에서 확인한 값은 강하게(품질 0.48, 긴 변 1,200px), 균형(0.68, 1,600px), 선명하게(0.84, 2,200px)다. 그런데 소스에는 페이지를 그릴 때 배율을 최대 2배(PDF 원래 크기의 2배)로 제한하는 부분이 있다. 이 상한 때문에 A4 문서에서는 단계의 이름보다 결과 차이가 작다. 이 값들은 소스 기준이라 도구가 바뀌면 달라질 수 있다.

검산해 보자. PDF의 길이 단위는 기본이 1/72인치다(PDF 라이브러리 문서의 UserUnit 설명). 도구 소개가 A4를 595×842포인트로 설명하므로 긴 변은 842/72 = 11.69인치(약 297mm)다. 여기에 긴 변 목표 픽셀을 나누면 해상도가 나온다.

단계 목표 긴 변 A4에서 실제 긴 변 환산 해상도
강하게 1,200px 1,200px (배율 약 1.43) 약 103dpi
균형 1,600px 1,600px (배율 약 1.90) 약 137dpi
선명하게 2,200px 1,684px (배율 2로 제한) 144dpi

즉 A4 문서에서 균형과 선명하게는 긴 변이 5% 정도(1,600px과 1,684px) 차이이고, 실제 차이는 JPEG 품질(0.68과 0.84)에서 난다. 용량이 목적이면 균형으로 시작하고, 글자가 뭉개지면 선명하게로 올리면 된다. 소개 문서의 안내(이메일 첨부가 목적이면 균형부터, 글자가 흐리면 선명하게, 아직 크면 강하게)와 같은 결론이다. 이미 최적화된 PDF나 글자 위주 PDF는 감소 폭이 작거나 결과가 더 커질 수 있고, 커지면 화면에 증가율이 표시되므로 그때는 원본을 그대로 쓴다.

20페이지가 넘는 문서는 압축 도구가 처리하지 않는다. 소개 문서가 안내하는 방법은 분할로 나눠 각각 압축한 뒤 합치기로 다시 이어 붙이는 것이다. 이때 압축본끼리 합치므로 각 조각이 이미지 페이지이며, 합친 뒤에도 글자 검색은 돌아오지 않는다.

제출용 PDF를 만드는 순서

여러 장의 서류를 한 파일로 만들어 제출하는 경우를 순서로 적는다. 이 순서는 위의 도구 동작에서 이끌어 낸 이 글의 권장이다.

  1. 휴대폰 사진은 먼저 PDF로. 이미지 PDF 변환기는 사진을 고른 순서대로 A4 한 쪽씩 담는다(최대 30장, 기본 여백 24pt, 긴 변을 2,400px로 줄여 JPEG 92%로 저장). 순서를 바꾸려면 만든 뒤 페이지 정리를 쓴다.
  2. 필요한 쪽만 뽑는다. 수십 쪽 문서에서 제출할 부분은 나누기로 범위를 추출한다. 예를 들어 1-3, 5, 8-10을 입력하면 3쪽+1쪽+3쪽으로 모두 7쪽짜리 새 파일이 된다. 같은 쪽 번호가 겹치면 한 번만 들어간다.
  3. 순서를 정리한다. 페이지 정리는 입력한 번호를 그 순서대로 복사한다. 12쪽 문서에 3, 1, 2를 쓰면 3쪽·1쪽·2쪽 세 장짜리가 된다. 3-5 같은 범위 표기는 지원하지 않으므로 3, 4, 5처럼 쓴다. 같은 번호를 두 번 쓰면 결과에도 두 번 들어간다.
  4. 합친다. 파일 이름 앞에 번호를 붙여 두면 목록에서 순서를 확인하기 쉽다. 12쪽·5쪽·8쪽 파일 세 개를 합치면 25쪽이며, 합친 뒤에는 총 쪽수와 순서를 눈으로 확인한다. 파일 20개·100MB를 넘으면 나눠 합친 뒤 결과끼리 다시 합친다.
  5. 용량이 크면 마지막에 압축한다. 제출처가 글자 검색이나 복사를 요구한다면 압축하지 않는다(압축 도구 소개도 제출용에는 맞지 않을 수 있다고 안내한다). 그때는 스캔본이라면 사진을 줄여서 다시 PDF로 만들고, 아니라면 제출처가 허용하는 크기로 나눠 보내는 방법을 먼저 생각한다. 압축한다면 제출처 제한에 맞는 가장 약한 단계를 고른다. 결과는 compressed.pdf 로 고정되니 원본과 다른 이름으로 저장한다.
  6. 서명과 워터마크는 압축 뒤에. 압축은 페이지를 이미지로 다시 만들기 때문에, 압축을 먼저 하면 서명 이미지가 한 번 더 손실 압축을 거치지 않는다. 서명을 넣은 뒤 압축하면 서명도 낮은 해상도 이미지의 일부가 된다.
  7. 원본을 남긴다. 압축본·이미지 변환본은 되돌릴 수 없으므로 원본 PDF를 덮어쓰지 않는다.

서명과 워터마크가 해 주는 것, 못 하는 것

PDF 서명 도구는 PNG 또는 JPG 서명 이미지를 선택한 페이지의 모서리나 하단 중앙에 배치한다. 소개 문서는 이 기능이 PDF 위에 이미지를 그리는 도구이며 인증서 기반 디지털 서명이 아니라고 명시한다. 디지털 서명이 무엇을 하는지는 PDF 서명 라이브러리 iText 문서의 설명이 분명하다. 문서 내용이 중간에 바뀌지 않았다는 확신(무결성), 문서의 출처에 대한 확신(진본성), 발행자가 작성 사실을 부인할 수 없다는 확신(부인 방지)이 목적이고, 문서에서 계산한 해시를 개인 키로 서명해 서명자의 인증서와 함께 저장하는 방식이다. 이미지를 올리는 방식은 이 중 어느 것도 제공하지 않는다(이 부분은 iText 문서가 아니라 작성자의 판단이다). 그래서 확인 도장 정도의 내부 서류에는 쓸 수 있지만, 법적 효력이 필요한 계약은 상대 기관이 요구하는 방식을 따라야 한다.

서명 이미지는 선만 있는 투명 PNG가 자연스럽게 얹힌다(서명·도장 이미지 만들기 도구는 가로 1,200px·세로 500px 투명 PNG를 만든다). 서명 폭은 도구 소스 기준 40pt에서 300pt 사이이고 페이지 가장자리 여백 24pt를 둔다. 출력 후 페이지와 크기를 반드시 확인한다.

워터마크는 검토본·초안·기밀처럼 문서 상태를 알리는 용도다. 두 도구(PDF·이미지) 소개 모두 워터마크만으로 복사나 편집을 기술적으로 막지는 못한다고 안내한다. PDF 워터마크는 PDF 기본 글꼴을 쓰므로 영문·숫자 문구에 맞고, 글자 크기 12–120, 투명도 5–80%, 각도 -90–90도 범위에서 낮은 투명도로 시작해 본문을 가리지 않는지 확인한다.

PDF를 이미지로 바꿀 때

PDF JPG·PNG 변환을 쓰는 이유는 슬라이드 한 장을 메신저로 보내거나 문서 한 쪽을 블로그에 올리는 경우다. 소개 문서의 권장은 사진이 많은 문서는 JPG, 글자와 선이 많은 문서는 PNG, 해상도는 2배부터 확인이다. 소스 기준 기본값은 2배이고 JPG 품질 0.88이다. 3배는 더 선명하지만 메모리와 저장 용량을 많이 쓰므로 모바일에서는 1.5–2배가 안정적이라고 안내한다. 변환된 이미지는 글자 검색이 되지 않으니 원본 PDF는 따로 둔다.

흔한 실수와 한계

  • 서명 뒤에 압축한다. 서명이 이미지의 일부로 낮은 해상도가 되거나, 전자서명 정보가 사라진다.
  • 압축본을 원본 자리에 저장한다. 글자 검색·링크가 영구히 사라진다.
  • 페이지 번호를 인쇄 번호로 센다. 책의 인쇄 쪽 번호가 아니라 PDF의 실제 순서(1부터)를 쓴다. 표지·목차가 앞에 있으면 두 값이 다르다.
  • 합친 뒤 확인하지 않는다. 순서와 총 쪽수, 링크·양식 동작을 열어서 본다.
  • 압축 도구가 20페이지 한도에서 막혀 다른 방법을 찾는다. 나누기→압축→합치기가 소개 문서의 방법이다.

이 글의 한계도 적는다. 한도와 동작은 이 사이트 도구 기준이라 다른 PDF 프로그램에는 그대로 적용되지 않는다. 해상도 환산은 A4 크기 문서 기준이고, 다른 용지·가로 문서는 긴 변이 다르다. 법적 서명 요건은 이 글에서 다루지 않았고 기관별 안내를 따라야 한다.

    사진 용량이 큰 이유를 픽셀 수로 계산하고, JPG·PNG·WebP·HEIC를 용도별로 비교해 품질 70–85%와 최대 너비를 고르는 기준을 공식 문서 수치와 함께 정리했다.

  • 이미지 규격표: 유튜브 썸네일·링크 미리보기·증명사진·앱 아이콘 크기와 자르는 법

    유튜브 썸네일, 링크 공유 미리보기(1200×630), 증명사진(3.5×4.5cm), 앱 아이콘(1024·512px)의 규격을 확인한 출처와 함께 표로 정리하고, 비율이 다른 사진을 잘리지 않게 맞추는 계산법을 적었다.
