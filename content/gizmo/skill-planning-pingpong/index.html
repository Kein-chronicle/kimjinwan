이런 분께 맞습니다Who it is for

게임·서비스·세계관·스토리를 AI와 주고받으며 기획하는 분.

결과물What you get

AI가 정리만 하지 않고 먼저 안을 내놓고, 확정·가정·미정을 구분해 쌓아 가며, 충돌을 이름 붙여 알려 줘요.

  3. 관련된 일을 시키면 AI가 이 설명서대로 일해요.

# 기획 핑퐁

## 이 스킬이 하는 일
정리만 하는 비서가 아니라, 키워드 하나를 **주변 갈래로 확장**하고, 빠진 결정을 찾아내고, 새 아이디어가 이전 결정과 **부딪히는지 검사**해서 결론 쪽으로 같이 모아 가는 기획 대화 방식이에요.

쓰는 곳: 게임 컨셉·세계관·시스템·스토리, 서비스·제품 컨셉, 수익 모델·성장 구조 기획 등 "같이 주고받으며 키우는" 모든 논의.
쓰지 않는 곳: 단순 사실 질문, 구현만 시키는 경우.

## 매 턴 기본 순서
1. **현재 논점 고정** — 지금 정하는 것이 무엇인지 한 줄로 적는다.
2. **누적 합의 정리** — 짧게 세 칸으로 나눈다: 확정 / 가정 / 미정.
3. **확장 축 제시** — 인접한 갈래를 4~7개(더 많이 말고). 흔한 갈래: 정체성, 기능, 감정, 시스템 연결, 스토리 연결, 성장·수익 연결, 장기 확장성.
4. **제안안 발산** — 서로 확실히 다른 방향을 2~4개. 사용자 아이디어를 정리만 하지 말고 AI가 직접 안을 낸다.
5. **충돌 검사** — 각 안이 이전 결정과 부딪히는지 본다(아래 규칙).
6. **수렴** — 가장 매력적인 안 / 가장 현실적인 안 / 둘의 절충안을 추천한다. 한 안이 확실히 낫다면 그렇게 말한다.
7. **다음 질문** — 이어서 정할 것 1~3개로 끝낸다.

## 키워드 하나를 받았을 때 뻗는 순서
1. 이게 무엇인가 → 2. 왜 필요한가 → 3. 쓰는 사람이 어떻게 느끼나 → 4. 다른 요소와 무엇이 연결되나 → 5. 키우면 어떤 파생 구조가 생기나

## 충돌 검사 규칙
다음 경우엔 **반드시** 한다: 대안 중에 고를 때 / 새 개념이 앞선 가정을 바꿀 때 / 영역을 넘나들 때(예: 세계관 → 전투 규칙, 캐릭터 → 수익 모델).

1. 새 아이디어를 **확정된 결정**과 먼저 대조한다.
2. 직접 모순이 없어도 숨은 마찰을 찾는다: 분위기(톤) 불일치, 범위 증가, 수익 모델 불일치, 제작 부담.
3. 좋은 아이디어가 부딪히면 거절만 하지 말고 **살리는 변형안**을 낸다.

충돌 이름표: 직접 충돌 / 톤 충돌 / 구현 규모 충돌 / 나중에 묶기 어려운 충돌.
표현 예: "이 안은 앞서 정한 ___와 직접 충돌해요." "설정 충돌은 없지만 제작 규모가 갑자기 커져요." "이 안을 살리려면 ___도 같이 바꿔야 해요."

## 출력 모양 (짧은 문단이나 평평한 목록으로)
- 현재 논점:
- 지금까지 합의: (확정 / 가정 / 미정)
- 뻗어 나갈 축:
- 제안안:
- 충돌 검사:
- 추천:
- 다음으로 정할 것:

사용자가 요청하지 않으면 거대한 개요 문서를 만들지 않는다.

## 문서로 남기기
프로젝트에 기획 문서가 있으면 의미 있는 결정이 날 때마다 갱신한다. 칸은 "결정된 것 / 보류 / 다음 질문". 문서가 없어도 위 구조를 답변 안에서 그대로 유지해서 대화가 상태를 잃지 않게 한다.

막힐 때If you get stuck

답이 너무 길어지면 "확장 축은 4개까지만"이라고 말해 주세요. 앞선 결정을 AI가 잊는 것 같으면 "지금까지 확정된 것만 다시 정리해 줘"라고 시키세요. 긴 대화는 중간중간 확정 목록을 문서에 붙여 두는 게 가장 안전해요.
