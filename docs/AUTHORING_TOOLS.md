# 웹 도구 소개 — 어디서 읽히고 무엇이 모자라면 빠지는가 (공장용)

웹 도구(`kein-web-tools`, apps.kimjinwan.com)는 허브에 **편집 원본이 없다.** 허브 생성기가 도구 저장소의 소스에서 소개 사실을 직접 읽는다. 그래서 공장(웹툴)이 할 일은 소개를 따로 쓰는 것이 아니라 **도구 소스에 사용자가 읽는 정적 한국어 문구를 충분히 두는 것**이고, 그 결과를 점검 CLI 로 확인하는 것이다.
읽는 코드: `scripts/lib/hub_sources.mjs` 의 `parseToolCatalog`·`collectTool`·`toolBodyChars`·`toolEligible`. 허브 빌드와 점검 CLI 가 같은 함수를 부른다.
허브 빌드·배포는 매일 06:30 content-hub-sync 가 한다. 도구 저장소 변경만 끝내면 되고 허브 저장소는 건드리지 않는다(이미지는 허브 쪽이 만든다).

## 1. 소개가 읽히는 곳(두 군데뿐)
| 곳 | 읽는 것 | 허브 화면에서의 쓰임 |
|---|---|---|
| `lib/tool-catalog.ts` 의 `tools` 항목 | `href`(`'/<slug>/'`)·`name`·`description`·`categories[0]` | 목록 카드(이름·한 줄 설명)·분류·상세 제목·설명 |
| `app/<slug>/page.tsx` 의 **정적 한국어 문구** | 아래 표 | 상세 페이지 본문 전체 |

`page.tsx` 에서 읽는 것(`collectTool`):
| 종류 | 어떤 코드가 읽히나 | 팁 |
|---|---|---|
| 머리말 | `<h1>도구 이름</h1>` **바로 뒤** `<p>한 줄</p>` | 둘이 붙어 있어야 한다. `{변수}` 가 들어 있으면 못 읽는다 |
| 입력 라벨 | `<label>`·`<Label>`·`<legend>` 의 텍스트, 입력 칸(`Input`·`Textarea`·`Select`)의 `aria-label="…"` | 무엇을 입력받는지가 소개에 실린다. 2~140자, 한글 포함, `{ } = <` 없음. '삭제·추가·초기화·복사·인쇄' 단독 라벨은 제외 |
| 버튼 문구 | `<Button>…</Button>` 안의 텍스트 | 동작 이름이 소개에 실린다 |
| 본문 문장 | `<h2>`·`<h3>`·`<p>`·`<li>`·`<dd>`·`<summary>` 안의 정적 한국어 + 24~260자 길이의 마침표로 끝나는 한국어 문자열 상수(안내·FAQ) | 사용 방법·주의점·한계를 문장으로. 문장 14자 이상(제목류 6자 이상), 420자 이하. 중복은 한 번만 |
| MCP 설명 | `registerWebMcpTool({… description: '…'})` | 있으면 "무엇을 받아 무엇을 내놓는지"로 쓰인다 |

읽히지 않는 것: `{변수}`·템플릿 보간이 섞인 문장, 오류·알림 문구(`throw new Error`, "복사했어요", "저장하지 못했어요", "다시 시도" 등), `className`·코드 조각, 영어 전용 문구, 이미지·아이콘 안의 글자. 소스 문구 속 '원문'은 허브에서 '원본'으로 바뀌어 실린다.

## 2. 허브 자격 기준(`toolEligible`)
세 가지를 모두 충족해야 한다. 하나라도 모자라면 허브에서 **제외**되고 사유가 `content-src/excluded.json` 에 남는다.
1. **출처 1개 이상**: `app/<slug>/page.tsx` 가 있어 읽혔다.
2. **본문 사실 분량 300자 이상**: `description` + 머리말 + 본문 문장 + 입력 라벨 + 버튼 문구의 합(중복 제외, 글자 수).
3. **입력 라벨·버튼·본문 문장 중 1개 이상**.

그 밖에 빌드가 요구하는 것:
- `categories[0]` 가 허용 분류: `이미지`·`PDF`·`QR`·`게임`·`생활·학습`·`업무`(`hub_sources.mjs` 의 `TOOL_IDS`). 다른 값이면 **허브 생성기가 예외로 멈춘다** — 새 분류는 허브 담당에게 요청한다.
- **화면 이미지**: 허브가 `build_content_images.mjs` 로 라이브 페이지 `https://apps.kimjinwan.com/<slug>/` 를 헤드리스 Chrome 으로 1280×800 캡처해 `assets/content/tools/<slug>.webp`(카드 640×400)·`<slug>-hero.webp`(1200×750)를 만든다. **공장이 캡처하지 않는다.** 도구가 배포되어 열려야 만들어지고, 이미지가 없으면 허브는 "이미지 없음"으로 제외한다(다음 허브 이미지 생성 때 해소).
- 화면에 실리는 문구에 **1인칭(제가·저는 …)·이모지·TODO 가 없어야 한다**(허브 시험이 막는다). 점검 CLI 가 미리 잡는다.

## 3. 부족할 때 고칠 위치
| 점검 출력 | 고칠 곳 | 방법 |
|---|---|---|
| `카탈로그 등록` 실패 | `lib/tool-catalog.ts` | `tools` 에 `{ href: '/<slug>/', name, description, keywords, icon, categories: ['…'] }` 추가 |
| `분류` 실패 | `lib/tool-catalog.ts` | `categories` 맨 앞을 허용 분류로 |
| `읽은 출처` 실패 | `app/<slug>/page.tsx` | 페이지 파일이 없다. 경로가 `href` 와 같아야 한다 |
| `입력 라벨 없음` | `page.tsx` | `<label>`·`<legend>` 텍스트 또는 입력 칸 `aria-label` 을 정적 한국어로 |
| `버튼 문구 없음` | `page.tsx` | `<Button>계산하기</Button>` 처럼 정적 문구 |
| `본문 문장 없음` | `page.tsx` | 사용 방법·한계를 `<p>`·`<li>` 정적 문장(14자 이상)으로 |
| `본문 사실 분량 N자 — M자 부족` | `page.tsx`, `description` | 사용 방법·입력 설명·알아둘 한계를 M자 이상 더. 억지로 늘리지 말고 실제 동작·제약을 쓴다 |
| `금지어` 실패 | `page.tsx`·`description` | 1인칭은 서술형으로, 이모지·TODO 삭제 |

실패 예(실제 도구 `image-crop-rotate`): 입력 라벨 2개 + 본문 5개가 읽히지만 버튼 문구가 없고 본문 분량이 242자(58자 부족) → 사용 방법·한계 문장을 더 쓰면 통과한다.
문구를 쓸 때 기준: 사용자가 화면에서 실제로 읽는 안내여야 한다(소개용 홍보 문장을 따로 만들지 않는다). 소개는 소스에서 확인되는 문장만 싣는다.

## 4. 점검 CLI
```
cd ~/Projects/kimjinwan
node scripts/hub_check_tool.mjs <slug> [--tools-repo <kein-web-tools 경로>] [--root <허브 저장소>] [--json] [--online]
```
- 기본 `--tools-repo` 는 `~/Projects/kein-web-tools`. 작업 중인 포크·워크트리면 그 경로를 준다.
- 종료 코드: **0 자격 충족 · 1 미달 · 2 사용법 오류.**
- 출력: 카탈로그 등록·분류·**읽은 출처(`app/<slug>/page.tsx`)**·머리말·입력 라벨·버튼 문구·본문 문장(각 개수와 앞부분 예시)·MCP 설명·분량 판정(N자/300자)·금지어·화면 이미지 유무와 생성 방법. 미달이면 모자란 것과 "다음 행동" 목록을 낸다.
- `--json`: `{ok, eligible, chars, sources, counts:{inputs,actions,blocks}, checks[], next[]}`.
- `--online`: `https://apps.kimjinwan.com/<slug>/` 가 200 인지 확인(미배포면 허브 이미지가 안 만들어진다).
- 화면 이미지가 허브에 아직 없으면 `[안내]` 로 표시한다(자격 판정에 영향 없음, 위 2절).

예
```
$ node scripts/hub_check_tool.mjs qr-reader
[통과] 읽은 출처 — app/qr-reader/page.tsx + 카탈로그 설명
[통과] 입력 라벨 — 2개: 'QR 이미지 선택', 'QR 해석 결과'
[통과] 본문 사실 분량(300자 이상) — 339자
결과: 통과

$ node scripts/hub_check_tool.mjs image-crop-rotate
[주의] 버튼 문구 — 0개: 없음
[실패] 본문 사실 분량(300자 이상) — 242자 — 58자 부족
결과: 실패 (1건)   (exit 1)
```

## 5. 웹툴 공장 체크리스트
1. 새 도구를 만들면 `lib/tool-catalog.ts` 에 등록하고 `app/<slug>/page.tsx` 에 입력 라벨·버튼·사용 방법 문장을 **정적 한국어**로 둔다(동적 문구에만 의존하지 않는다).
2. `node scripts/hub_check_tool.mjs <slug>` 를 돌려 exit 0 을 확인한다. 미달이면 3절 표대로 고치고 다시 돌린다. 미달을 못 고치는 도구(설명할 거리가 정말 없는 도구)는 그대로 둔다 — 허브에서만 제외되고 도구에는 영향이 없다.
3. 도구를 배포한다(도구 쪽 절차). 허브 이미지·빌드·배포는 06:30 content-hub-sync 가 한다.
4. 허브 저장소에는 아무것도 커밋하지 않는다.

## 6. 흔한 실패
| 증상 | 원인 | 해결 |
|---|---|---|
| `tool catalog parse mismatch` | 카탈로그 항목이 `{href, name, description, …, categories:[…]}` 형식이 아니다(다른 키 순서·템플릿 문자열) | 형식을 기존 항목과 같게 맞춘다(`href`→`name`→`description` 순) |
| 입력은 있는데 `입력 라벨 0개` | 라벨이 `{t('…')}` 같은 보간이거나 `<label>` 대신 `<div>` | 정적 한국어 `<label>` 로 쓰거나 입력 칸에 `aria-label="…"` |
| 문장이 많은데 `본문 문장 0개` | 문장이 `{…}` 를 포함하거나 14자 미만이거나 `<span>` 안에 있다 | `<p>`·`<li>` 안에 변수 없이 완결 문장으로 쓴다 |
| 허브에 도구는 있는데 이미지가 없어 제외 | 도구가 아직 배포 전이거나 캡처가 비었다(색이 40가지 미만) | 도구를 배포·정상 렌더되게 한다. 이후 허브가 생성 |
