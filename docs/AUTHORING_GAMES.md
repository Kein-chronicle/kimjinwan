# 웹게임 소개 작성 원본 — 공장(게임 포지)용

이 문서만 읽고 `data/authoring/games/<id>.json` 을 쓰고 점검까지 끝낸다. 대상 사이트: kimjinwan.com `/content/games/<id>/`.
규칙의 단일 출처는 코드다: `scripts/lib/games_authoring.mjs`(`validateAuthoring`·`imageProblems`). 허브 빌드와 점검 CLI 가 같은 함수를 쓰므로 CLI 가 통과하면 빌드도 통과한다.

## 1. 큰 그림(하이브리드)
- **편집 원본이 있는 게임**: `data/authoring/games/<id>.json` 의 서술을 그대로 쓴다(검증·이미지가 맞을 때만).
- **편집 원본이 없는 게임**: 기존 소스 추출(README·설계 문서·`games.json` 설명, `scripts/lib/hub_sources.mjs`)로 소개를 만든다. 사실이 모자라면 제외된다(`content-src/excluded.json` 에 사유).
- 같은 게임이 양쪽에 가능하면 **편집 원본이 이긴다**. 편집 원본이 검증·이미지에서 실패하면 그 게임만 소스 추출로 되돌아가고(빌드는 계속) 허브 빌드가 stderr 에 경고를 낸다. 소스 추출도 안 되면 제외된다 — 즉 **고치지 않고 두면 조용히 빠진다.** 그래서 쓴 뒤에 반드시 점검 CLI 를 돌린다.
- 장르(`games.json` 의 `categories[0]`)·한 판 길이·조작 라벨·화면 방향 같은 **메타는 편집 원본에 쓰지 않는다**(`games.json` 에서 온다). 서술만 쓴다.
- 허브 빌드·배포는 매일 06:30 content-hub-sync 가 한다. 공장은 아래 경로만 커밋한다.

## 2. 작성 기준(가장 중요)
1. **직접 실행해서 본 것만 쓴다.** 게임을 실제로 열어 조작하고 본 화면·문구·숫자만 적는다. README·기획서에만 있고 확인 못 한 내용은 쓰지 않는다. 확인 못 한 것은 `verified.notes` 에 "확인 못 함: …" 으로 적는다.
2. 본문은 **500자 이상**(공백 제외, 아래 `본문` 에 들어가는 모든 필드의 합). 억지로 늘리지 않는다. 쓸 사실이 모자라면 편집 원본을 만들지 말고 제외한다(5절).
3. 서술형 평서문. **1인칭 금지**(제가·저는·저의·저를·저에게·제게·저희·"제 …"). "직접 …" 표현을 쓴다. 이모지 금지.
4. 금지어: '원문', '기즈모', 'gizmo'(대소문자 무관). 내부 공정 용어도 본문·이미지 설명에 쓰지 않는다: `Forge`·`게이트`·`검증`·`빌드`·`렌더`·`스타터`·`파이프라인`·`QA`·`DoD`·`원작`·`리서치`·`라이선스`·`CC0`·`OpenAI`·`localStorage`·`런타임`·`manifest`·파일 경로(`.json`·`.md`·`.ts`·`public/`) 등(정확한 목록은 `hub_sources.mjs` 의 `INTERNAL`). 플레이어가 쓰는 말로 쓴다. `verified` 는 화면에 나오지 않아 내부 용어를 써도 된다(날짜만 "YYYY-MM-DD 직접 실행해 확인한 내용입니다"로 나온다).
5. 근거 없는 홍보 문구("중독성 최고", "누구나 즐길 수 있는")를 쓰지 않는다. 숫자·이름·화면에 보인 문구 위주로 쓴다.
6. 게임이 아직 공개 주소(`https://games.kimjinwan.com/play/<id>/`)에서 200 이 아니면 올리지 않는다.

## 3. 필드 정의
파일명 = `<id>.json`, `id` 는 `games.json` 의 slug 와 같다.

| 필드 | 형식 | 규칙 | 화면에서의 위치 |
|---|---|---|---|
| `id` | 문자열 | 파일명과 같아야 한다 | — |
| `oneLiner` | 문자열 | 1문장, 이 게임이 무엇이고 무엇을 하는지(색인 카드 요약도 이것) | 상단 요약·목록 요약·메타 설명 |
| `about` | 문자열 | 게임의 첫인상·화면 구성·분위기. 문단은 `\n` 으로 나눈다 | "이런 게임입니다" |
| `controls.pc` / `controls.touch` | 문자열 배열 | 둘 중 **하나 이상**. 실제로 확인한 입력만(터치를 안 해 봤으면 `touch` 는 비운다) | "조작 방법" |
| `goal` | 문자열 | 이기는 조건·목표 | "목표와 규칙" |
| `rules` | 문자열 배열 | 2개 이상. 실제로 본 규칙·점수·판정 | "목표와 규칙" |
| `progress` | 문자열 배열 | 1개 이상. 스테이지·난이도·해금 구조 | "진행" |
| `tips` | 문자열 배열 | **2~3개**. 실제로 해 보고 얻은 팁 | "처음 하는 사람을 위한 팁" |
| `screens` | 문자열 | 로비·플레이·결과 화면이 어떻게 생겼는지 | "플레이 화면"(캡처 위 문단) |
| `images` | 배열 | **2~4장**(6절) | 대표 이미지·갤러리 |
| `cardIndex` | 정수(선택) | 목록 카드로 쓸 `images` 번호. 생략하면 첫 비-타이틀 이미지 | 목록 카드 |
| `verified` | 객체 | 7절 | 날짜만 표시 |

본문 합산에 들어가는 필드: `oneLiner`, `about`, `controls.*`, `goal`, `rules`, `progress`, `tips`, `screens`.

## 4. 복사해서 쓰는 템플릿
`<id>` 와 `…` 를 채운다. 문장 수·길이는 예시이고 기준은 2절이다. 완성 예시: [`aim-trainer.json`](../data/authoring/games/aim-trainer.json)(훈련·액션), [`clockwork-harbor.json`](../data/authoring/games/clockwork-harbor.json)(퍼즐), [`arc-eel.json`](../data/authoring/games/arc-eel.json)(퍼즐·이미지 4장).

```json
{
  "id": "<id>",
  "oneLiner": "…를 …하는 …게임입니다.",
  "about": "첫 화면은 …이고, 플레이 화면은 …다. …",
  "controls": {
    "pc": ["마우스로 …를 클릭한다.", "키보드 …로 …한다."],
    "touch": ["화면의 …를 탭한다."]
  },
  "goal": "…를 …해 …를 달성한다.",
  "rules": [
    "…하면 …점이 오르는 것을 볼 수 있었다.",
    "…하면 …이 실패로 처리되고 …가 나온다."
  ],
  "progress": [
    "…스테이지가 …개 있고 …을 하면 다음 스테이지가 열린다."
  ],
  "tips": [
    "처음에는 …부터 하면 …다.",
    "…를 먼저 확인해 두면 …를 줄일 수 있다."
  ],
  "screens": "로비에서는 …가 보인다. 플레이 화면은 …가 위에, …가 아래에 있고, 결과 창에는 …가 나온다.",
  "images": [
    {"src": "<id>-0.png", "role": "title", "alt": "시작 화면. …가 보이고 …버튼이 있다"},
    {"src": "<id>-1.png", "role": "play", "alt": "…스테이지 플레이 화면. …가 …에 놓여 있다"},
    {"src": "<id>-2.png", "role": "result", "alt": "한 판을 마친 결과 창. …와 …가 표시된다"}
  ],
  "verified": {
    "date": "2026-10-13",
    "method": "헤드리스 Chrome 으로 로컬 빌드를 열고 …를 한 판 끝까지 플레이했다.",
    "notes": [
      "…스테이지 1판: …점, …회로 클리어.",
      "콘솔 오류 없음.",
      "확인 못 함: …스테이지 이후, 터치 입력, 소리."
    ]
  }
}
```

## 5. 새 게임 추가 절차(게임 포지 6항)
1. 게임이 공개(done)되어 `games.json` 에 있고 `https://games.kimjinwan.com/play/<id>/` 가 열리는지 확인한다.
2. 게임을 직접 실행해 플레이하며 관찰한다(규칙·점수·화면 문구·실패 처리·스테이지 구조). 같은 시각에 6절의 캡처 PNG 를 찍는다.
3. 4절 템플릿으로 `data/authoring/games/<id>.json` 을 쓴다.
4. 이미지를 만든다(PNG 는 저장소 밖 폴더에 둔다).
   ```
   cd ~/Projects/kimjinwan
   node scripts/build_content_images.mjs --raw <캡처 폴더>
   ```
   `images[].src` 파일을 `<캡처 폴더>` 에서 읽어 `assets/content/games/<id>*.webp` 를 만들고 `content-src/images.json` 매니페스트를 갱신한다(이 slug 만 다시 만들고 다른 게임 이미지는 건드리지 않는다). 헤드리스 Chrome·Pillow(python3)가 필요하다.
5. 점검한다(8절): `node scripts/hub_check_game.mjs <id> --online --raw <캡처 폴더>` → **exit 0 이어야 한다.**
6. 아래 경로만 커밋한다. 다른 파일은 건드리지 않는다.
   - `data/authoring/games/<id>.json`
   - `assets/content/games/<id>*.webp` (`<id>.webp`·`<id>-hero.webp`·`<id>-1..3.webp`)
   - `content-src/images.json` (매니페스트가 바뀐다)
7. 빌드·배포는 하지 않는다(06:30 content-hub-sync 가 한다).

**사실이 모자라 쓰지 않기로 했을 때**: 파일을 만들지 말고 `data/authoring/games/_progress.json` 의 `excluded` 에 사유를 적고 커밋한다. 그러면 허브는 이 게임을 소스 추출로도 시도하지 않고 제외하며 사유를 `excluded.json` 에 남긴다. 점검 CLI 는 "제외 확정"(exit 0)으로 답한다.
```json
{"note": "…(그대로 둔다)", "excluded": [
  {"id": "<id>", "reason": "직접 실행했지만 시작 화면 뒤로 진행되지 않아 쓸 사실이 없음", "evidence": "콘솔 오류 …"}
]}
```
사유 없이 파일만 없으면 점검 CLI 는 "제외 예정"(exit 1)을 출력한다: 소스 추출로 자격이 되면 기존 방식 소개가 만들어지고, 안 되면 조용히 제외된다.

## 6. 이미지 규칙
- **2~4장.** `images[0]` = 대표(hero) 이미지, 보통 `role: "title"`(시작·로비 화면). 나머지는 갤러리 순서. **타이틀 외에 `play` 또는 `result` 가 1장 이상** 있어야 한다.
- 항목: `{"src": "<파일명>.png", "role": "title|play|result", "alt": "…"}`. `src` 는 PNG 파일명(경로 없이), 서로 달라야 한다.
- `alt` 는 **12자 이상**, 화면에 실제로 보이는 것을 문장으로 설명한다(이모지·1인칭·내부 용어 금지, 본문과 같은 규칙).
- 캡처는 **직접 플레이하며 찍은 실제 화면**이다. 표지·홍보 그림·합성 이미지는 쓰지 않는다. 가로 게임은 1280×720 안팎, 세로 게임도 그대로 올리면 된다(대표 이미지는 가로 비율이 아니면 블러 배경 위에 얹어 1280×720 으로 만든다).
- 결과물과 크기 예산(`IMG_BUDGET`, 한 곳에서 정의): 카드 `<id>.webp` 640×400 · **40KB 이하**, 대표 `<id>-hero.webp` 폭 **1280 이하 · 150KB 이하**, 화면 `<id>-1..3.webp` **150KB 이하**. 변환기가 화질을 낮춰 맞추지만 그래도 넘으면(복잡한 화면) 점검이 실패한다 — 캡처를 단순하게 다시 찍는다.
- 서브도메인 핫링크를 쓰지 않는다. 허브가 자체 호스팅한다.
- 이미지 목록(`images[].src`·`cardIndex`)을 바꾸면 변환기를 다시 돌려야 한다. 매니페스트의 `from` 서명이 편집 원본과 다르면 허브는 그 편집 원본을 쓰지 않는다.

## 7. verified 작성법
```json
"verified": {"date": "YYYY-MM-DD", "method": "…", "notes": ["…", "…"]}
```
- `date`: 실제로 실행한 날(YYYY-MM-DD). 화면에는 "2026-10-13 직접 실행해 확인한 내용입니다."로 나온다.
- `method`: 어떻게 실행했는가 한 문장(헤드리스 Chrome 으로 로컬 빌드를 열고 클릭 입력으로 …).
- `notes`: **2개 이상.** 관찰한 구체 결과(점수·횟수·화면 문구)와, 마지막에 반드시 **"확인 못 함: …"** 으로 못 본 것(터치 입력·소리·후반 스테이지·시험하지 못한 모드)을 적는다. 본문 서술은 notes 안에서 확인된 범위를 넘지 않는다.
- `verified` 에는 '원문'·'기즈모' 어휘를 쓰지 않는다(내부 공정 용어는 허용).

## 8. 점검 CLI
허브 저장소(`~/Projects/kimjinwan`)에서 실행한다. 공장 저장소 밖에서도 `cd ~/Projects/kimjinwan && node scripts/hub_check_game.mjs …` 로 부른다.
```
node scripts/hub_check_game.mjs <id> [--json] [--online] [--raw <캡처 폴더>] [--root <허브 저장소>] [--games-repo <kein-web-games>]
```
| 옵션 | 뜻 |
|---|---|
| (없음) | 사람이 읽는 체크리스트. 통과 exit 0, 실패 exit 1, 사용법 오류 exit 2 |
| `--json` | 같은 내용을 JSON(`ok`·`checks[{status,label,detail,hint}]`·`next[]`)으로 |
| `--online` | `https://games.kimjinwan.com/play/<id>/` 가 200 인지 확인 |
| `--raw <폴더>` | `images[].src` PNG 가 그 폴더에 있는지 확인 |
| `--root`, `--games-repo` | 허브 저장소·`games.json` 위치를 바꾼다(기본: 이 저장소, `~/Projects/kein-web-games`) |

점검 항목: 편집 원본 존재 · JSON 문법 · 장르가 허용 목록인지 · 필수 필드 · 본문 길이 · 금지어(1인칭·이모지·원문·기즈모·내부 공정 용어) · verified · 이미지 정의 · 이미지 파일·매니페스트 일치와 크기 예산 · (옵션) 캡처 원본·게임 주소. 파일이 없으면 "제외 예정"(또는 `_progress.json` 에 기록돼 있으면 "제외 확정")을 출력한다. 실패하면 항목마다 무엇을 어떻게 고칠지(→)와 "다음 행동" 목록을 낸다.

## 9. 흔한 실패와 해결
| 증상(점검 출력) | 원인 | 해결 |
|---|---|---|
| `본문 N자 < 500자` | 확인한 사실이 적다 | 더 플레이해서 규칙·화면 문구를 추가 관찰한다. 그래도 모자라면 제외(5절) |
| `1인칭(제가·저는 …) 금지` | "저는 …해 봤다" | "직접 …해 보니 …였다" 같은 서술로 바꾼다 |
| `내부 공정 용어('검증') 금지` | 본문·alt 에 개발 용어 | 플레이어 시점의 말로 바꾼다("검증" → "확인", "빌드" → 삭제) |
| `'원문'·'기즈모' 어휘 금지` | verified 포함 전체 | "원본"으로 바꾸거나 삭제 |
| `images 는 2~4장` / `플레이 중/결과 화면이 1장 이상 필요` | 캡처 수·role | 2~4장으로 맞추고 `play`·`result` 를 최소 1장 넣는다 |
| `images 항목은 {src(파일명.png), role, alt 12자 이상}` | alt 가 짧거나 role 오타 | alt 를 문장으로, role 은 `title|play|result` |
| `이미지 매니페스트 없음` / `…src·cardIndex 와 다르다` | 변환기를 안 돌렸거나 목록을 바꾼 뒤 안 돌렸다 | `node scripts/build_content_images.mjs --raw <폴더>` |
| `…webp NKB > MKB` | 캡처가 복잡해 예산 초과 | 더 단순한 장면으로 다시 캡처한다 |
