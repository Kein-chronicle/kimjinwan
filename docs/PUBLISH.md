# 허브 발행 — scripts/publish.sh

게임 포지·웹툴 공장, 기즈모 스토어 등록, 사람이 **허브(kimjinwan.com)를 발행하는 유일한 길**이다. 같은 저장소(~/Projects/kimjinwan, 브랜치 `static-site-2026`)에서 한 번에 한 발행만 돈다.

```
cd ~/Projects/kimjinwan
scripts/publish.sh --reason "게임 <id> 허브 등록"     # 실제 발행
scripts/publish.sh --reason "..." --dry-run            # 끝까지 점검하되 업로드·전환·커밋 없이 작업트리 원상복구
scripts/publish.sh --reason "..." --force              # 소스 변화가 없어도, 변동 게이트에 걸려도 진행(사람 확인 후에만)
```
서비스 목록만 수정할 때는 `--services-only`를 사용한다. 기존 콘텐츠 스냅샷을 보존하고 서비스 목록·공유 카드만 다시 빌드한다. 변동 게이트·전체 시험·버전 상승·라이브 검증은 동일하게 수행한다. 형제 저장소의 작성 중 콘텐츠가 섞이는 것을 방지한다.

옵션: `--no-push`(커밋 후 푸시 생략), `--as-of YYYY-MM-DD`.

## 시작 조건
허브 작업트리가 **깨끗**하고 브랜치가 `static-site-2026` 이어야 한다(아니면 종료 코드 2, 어떤 파일이 더러운지 출력). 공장이 방금 만든 파일(편집 원본·이미지 등)은 **먼저 커밋**하고 호출한다.

## 하는 일(순서)
1. 잠금(`/tmp/kimjinwan-publish.lock`): 살아 있는 다른 발행이 있으면 종료 코드 75(건드리지 않음). 죽은 소유자의 낡은 잠금은 치운다.
2. 소스 스냅샷(`build_content_hub.mjs` — 블로그 dist·기즈모 API·웹게임·웹 도구·편집 원본) → 이미지(`build_content_images.mjs`, 없는 것만) → 빌드 → 공유 카드 재생성(`build_og.mjs`; 카드 문구에 글 편수가 들어 있어 새 글마다 `og-cards.lock.json` 이 어긋난다, 2026-10-14 블로그 허브 발행 첫 시험에서 시험 4번 실패로 발견) → 재빌드. 바뀐 게 없으면 종료 코드 10(`--force` 가 없을 때).
3. **변동 게이트**: 섹션별 개수가 줄었거나 한 번에 +20 을 넘으면 변경을 되돌리고 종료 코드 3(사람 확인).
4. 전체 시험(`node --test tests/*.test.mjs`) 통과 필수, `ads.txt`·`app-ads.txt` 해시 불변 확인. 실패하면 되돌리고 종료 코드 4(또는 해시 위반 3).
5. 서버 사전 점검(ssh, 새 버전 디렉터리가 비어 있는지) → 종료 코드 6 이면 되돌림.
6. 버전 패치 +1, DEPLOYMENT.md 맨 위에 발행 기록 한 단락, **커밋**(`publish: <이유> (<버전>)`), 푸시(실패해도 배포는 계속하고 경고).
7. 업로드 → `/var/www/kimjinwan/releases/<버전>`(root 소유, 755/644, 서버에서도 ads 해시 확인) → `current` 원자 전환.
8. **라이브 검증**: 주요 페이지 200, 홈·`/content/`·`/content/games/` HTML 해시가 로컬과 같음, `ads.txt`·`app-ads.txt` 해시, 이번에 바뀐 허브 페이지 최대 3개의 해시. **하나라도 실패하면 즉시 직전 릴리스로 롤백**하고 종료 코드 5(커밋은 남으므로 원인 수정 후 다시 발행).
9. 옛 릴리스 정리: 최근 6개만 남기고 `current` 는 절대 지우지 않는다.

## 종료 코드 요약
| 코드 | 뜻 | 호출자가 할 일 |
|---|---|---|
| 0 | 발행 완료(새 버전 출력) | summary 에 버전·커밋·상세 URL |
| 10 | 바꿀 게 없음 | 소스 반영이 맞는지 점검 CLI 로 확인(이미 반영됐거나 소스가 비었다) |
| 75 | 다른 발행 진행 중 | 2~3분 뒤 한 번 더. 그래도 75 면 대기로 보고 |
| 2 | 작업트리가 더럽다/브랜치 다름 | 내용을 확인해 먼저 커밋(시험 통과 확인) 후 재호출 |
| 3 | 변동 게이트 또는 ads 해시 위반 | **사람 확인 필요** — 되돌려졌다. 섹션·건수·대표 3건을 대기로 보고 |
| 4 | 스냅샷·이미지·빌드·시험 실패(되돌림) | 로그(`/tmp/kimjinwan-publish-*.log`)로 원인을 고치고 재발 방지 후 재호출 |
| 5 | 배포 검증 실패(자동 롤백됨) | 라이브는 직전 릴리스로 복구됨. 원인을 고쳐 재발행, 반복되면 롤백 유지하고 보고 |
| 6 | 서버 사전 점검 실패(ssh·버전 충돌) | 같은 버전 디렉터리가 있으면 건드리지 말고 대기. ssh 실패면 환경 확인 |

## 호출 예
- 게임: `scripts/publish.sh --reason "게임 <id> 허브 등록"`
- 도구: `scripts/publish.sh --reason "도구 <slug> 허브 등록"`
- 앱: `scripts/publish.sh --reason "앱 <이름> 허브 등록"`(편집 원본·이미지·스냅샷을 먼저 커밋, docs/AUTHORING_APPS.md)
- 기즈모 항목: `scripts/publish.sh --reason "AI 활용 가이드 <slug> 반영"`
- 사람 수동 점검: `scripts/publish.sh --reason "점검" --dry-run --force`

## 한계
- 소스 접근(네트워크·블로그 dist 부재) 실패는 생성기가 기존 산출을 보존한 채 실패하고 종료 코드 4 로 끝난다 — 불완전한 산출로 배포하지 않는다.
- 서버 접속(`ssh -i ~/kjw.pem ubuntu@54.116.13.147`)과 sudo 는 이 PC 에서만 된다.
- 롤백은 `current` 심볼릭 링크만 되돌린다(서버 파일·git 커밋은 남는다).
