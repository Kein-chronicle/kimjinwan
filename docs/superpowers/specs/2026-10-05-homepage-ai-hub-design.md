# kimjinwan.com 개편 설계 — AI 제작·운영 허브

날짜: 2026-10-05 / 상태: 설계 승인(구조·디자인), 구현 전

## 목표
이력 중심 포트폴리오를 "AI로 서비스를 만들고 직접 운영하는 사람"의 허브로 바꾼다.
경력은 유지하되 첫인상의 주역은 (1) AI 활용 능력 (2) 직접 만들어 운영하는 서비스 (3) 서비스를 찍어내는 AI 공장·파이프라인이다. 작업물은 계속 늘어난다.

## 제약
- 정적 사이트 유지(프레임워크 없음). 한·영 토글 유지.
- 애드센스 심사 제출 상태: `ads.txt`, `app-ads.txt`, 공개 콘텐츠 허브 링크, 메타/구조화데이터는 보존. 배포 규칙은 `DEPLOYMENT.md`를 따른다.
- 운영 브랜치 `static-site-2026`.
- 서브도메인(games / apps / blog / forge / prism-studio)은 그대로 두고 홈에서 모아 보여준다.

## 정보 구조
| 경로 | 내용 |
|---|---|
| `/` | 허브: 히어로(사람 한 줄 + 지표) → 대표 서비스 월 → 공장 섹션 → 컬렉션 4칸 → AI 활용 방식 → 경력 압축 타임라인 → 연락 |
| `/works` | 전체 작업물, 종류별 필터(서비스/게임/도구/앱/블로그) |
| `/factories` | 공장 상세(단계, 역할 분리, 수치, 산출물) |
| `/career` | 기존 경력·프로젝트 55개(내용 유지) |

주역은 C안: 상단은 사람 한 줄, 바로 아래부터 작업물 월.

## 데이터 (SSOT)
- `data/services.json`: `id, name{ko,en}, summary{ko,en}, kind(service|game|tool|app|blog), status(live|released|experiment), ai_tools[], url, thumb, featured(bool), updated`
- `data/factories.json`: `id, name{ko,en}, role{ko,en}, stages[{name, kind(ai|human|gate)}], human_role{ko,en}, metrics[{label, value, as_of}], outputs[service id]`
- 홈 지표(서비스·게임·앱·글 수)는 `services.json`에서 자동 집계. 새 작업물 = JSON 한 항목 추가.
- 기존 `js/data.js`(프로젝트 55개)는 `/career`용으로 유지.

## 공장 섹션
카드 1장 = 공장 1개. 구성: 이름·한 줄 역할 / 가로 단계 흐름도(기획 → 생성 → 검증 게이트 → 심사·배포, 실제 파이프라인 단계명 사용) / AI·사람 역할 분리 표기 / 실측 수치(갱신일 포함) / 산출물 링크.
대상: App Factory(iOS), Faith Factory, 웹게임 파이프라인, 영상 자동화, 블로그(AI 초안 + 사람 승인).
공개 수위: 개념·역할·단계·수치까지. 비공개: 프롬프트 원문, 내부 경로, 비용 상세, 계정·키·ID, 홀드 프로젝트.

## 디자인
- 톤: 절제된 엔지니어링 문서 사이트(Linear/Stripe Docs 계열). 신뢰감·정돈.
- 배경 웜 화이트(#FAFAF7 근처) + 잉크 텍스트, 다크 모드는 토큰으로 지원. 면 구분은 1px 헤어라인.
- 포인트 컬러 하나(딥 블루/인디고)만 링크·LIVE 배지·흐름도 강조에 사용. 그래디언트 제거. 상태색(LIVE 초록, 실험 앰버)은 기능용.
- 타이포: Pretendard + 숫자·버전·단계명·배지는 모노스페이스.
- 12컬럼 그리드, 섹션 번호 라벨(01 Services, 02 Factories …).
- 서비스 카드: 스크린샷 + 이름 + 한 줄 + 종류/상태 배지 + AI 툴 칩. 공장 카드: 파이프라인 다이어그램 + 역할 분리 + 수치.
- 모션 최소(호버 보더 강조). 모바일 1열, 흐름도는 세로 스택.
- 신뢰 장치: 수치에 갱신일, 모든 작업물에 실제 라이브 링크.

## 구현 순서(안)

## 개정 (2026-10-05, 유저 지시 — 시안 확인 후)
1. **주체는 사람이다.** 이 사이트는 사람을 보여주는 곳이다. 카피를 "운영합니다"가 아니라 "AI로 만들고 운영하는 **개발자 · PM 김진완**" 방향으로 바꾼다. 히어로뿐 아니라 섹션 제목·공장 설명·"사람 몫"→"제가 맡는 일"·컬렉션 설명·AI 섹션·경력 요약까지 1인칭/사람 중심으로 갈무리한다. 사실이 아닌 주장은 쓰지 않는다(수치·구조는 그대로).
2. **시간 기반 테마.** 낮에는 화이트, 해가 진 뒤에는 블랙. 방문자 현지 시각과 날짜로 일출/일몰을 근사 계산(한국 위도 기준 폴백)해 `data-theme` 를 정한다. 깜빡임 방지를 위해 `<head>` 인라인 스크립트로 먼저 적용하고, 열어둔 채로도 주기적으로 재평가한다. JS 없으면 라이트. OS 다크 설정은 따르지 않는다(유저 지시: 시간 기준).
3. **아이콘.** 거의 모든 항목에 의미 아이콘을 넣는다: 섹션 라벨, 지표, 서비스·컬렉션 종류, 공장별, 단계 종류(AI/GATE/HUMAN), 연락처 링크, 내비게이션 외부링크 표시. 인라인 SVG 라인 아이콘(외부 의존성 없음, `currentColor`).
